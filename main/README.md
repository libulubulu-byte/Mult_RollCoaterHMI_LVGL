# Roll Coater HMI —— main 组件说明

800×480 电容触摸 HMI，用于辊涂机高度轴。多屏结构：

- **主菜单 MAIN MENU**（`ui_menu.c`，界面稿 `ui1_main.png`）：5 个入口卡片
- **MOTOR TEST 子界面**（`ui_main.c`，界面稿 `rollcoater_main_screen_v3.png`）：
  读数卡片 + 数字键盘 + STOP —— 就是原来的辊涂机主屏
- **Admin 参数屏**（`ui_admin.c`）：在 MOTOR TEST 里输入 `9.999` 并长按 Enter 3 秒进入
- 状态机（State1/2/3 + Admin + Alarm）、STEP/DIR 步进轴控制（RMT 脉冲 + 梯形曲线）

- 工程目录：`examples/get-started/Mult_RollCoaterHMI/`
- CMake 工程名：`roll_coater_hmi`，固件：`build/roll_coater_hmi.bin`
- ESP-IDF ≥ 5.2（`esp_lvgl_port` 2.x 的下限；本工程在 5.5.1 上验证）
- LVGL 8.3.11 + `espressif/esp_lvgl_port` 2.9.0

## 1. 烧录与运行

```bash
cd examples/get-started/RollCoaterHMI
idf.py set-target esp32s3       # 首次
idf.py build
idf.py -p COM7 flash monitor    # 端口按实际改
```

`set-target` 只在首次需要；之后直接 `idf.py build flash monitor`。

> 改了 `sdkconfig.defaults` 后要让改动生效，必须删掉 `sdkconfig` 再 build
> （IDF 只在 `sdkconfig` 不存在时才用 defaults 生成它）；或者直接 `idf.py menuconfig`。

### 1.1 屏幕结构与导航

```
          上电
           │
           ▼
  ┌──────────────────────────┐
  │  主菜单 MAIN MENU         │   ui_menu.c    （界面稿 ui1_main.png）
  │  LIGHT  ENVIRONMENT       │   5 张卡片
  │  MOTOR TEST  HISTORY      │
  │  SETTINGS                 │
  └────────────┬─────────────┘
               │ 点 MOTOR TEST 卡片（本工程唯一可用的入口）
               ▼
  ┌──────────────────────────┐
  │  MOTOR TEST 子界面        │   ui_main.c    （界面稿 rollcoater_main_screen_v3.png）
  │  ‹ MOTOR TEST   State 1   │   读数卡片 + 数字键盘 + STOP
  └────────────┬─────────────┘
               │ 输入 9.999 后长按 Enter 满 3 秒
               ▼
  ┌──────────────────────────┐
  │  Admin - Machine Params   │   ui_admin.c
  └──────────────────────────┘
```

**MOTOR TEST 子界面怎么回主菜单**（两种方式都可用）：

| 方式 | 操作 | 判据 |
|---|---|---|
| 返回键 | 点顶栏左上角的圆形 `‹` | 日志 `ui_main: Back to MAIN MENU (back button)`；屏幕出现 5 张卡片 |
| 手势 | 在屏幕上**从右向左快划** | 日志 `ui_main: Back to MAIN MENU (swipe)`；屏幕出现 5 张卡片 |

手势的两个硬条件（LVGL 内部规则，不满足就是"划了没反应"——这最容易被误判成 bug）：

- **必须快划**：手指每次采样移动要 >3px（`LV_INDEV_DEF_GESTURE_MIN_VELOCITY`）。
  用指头**慢慢拖**到 50px 是**不触发**的。
- **累计位移 >50px，且横向分量大于纵向**（`LV_INDEV_DEF_GESTURE_LIMIT`）。
  竖着划会判成 `LV_DIR_TOP/BOTTOM`，不当返回（日志 `Gesture dir N ignored`）。

**返回前会自动做三件事**（`ui_main.c` 的 `main_go_back()`）：停轴
（`app_motion_stop()`）、关掉弹窗（`ui_popup_close()`）、清空输入缓冲区。
所以"划回去"不会留下一个还在跑的轴，也不会有弹窗盖在主菜单上。

> ⚠ 有弹窗待回答时（报警确认窗 / State3 的确认弹窗）**返回会被挡下**并打日志
> `Back ignored (swipe): a popup is waiting for an answer` —— 先把弹窗按钮点掉再返回。

**其余 4 个入口（LIGHT / ENVIRONMENT / HISTORY / SETTINGS）目前是占位**：
卡片按界面稿画出来了，点一下会在屏幕下方弹一条 `xxx not available yet` 提示条
（2.2 秒后自动消失），日志 `ui_menu: xxx tapped: screen not implemented yet`。
需求只确认了 MOTOR TEST 这一个入口，其余等后续规格。

## 2. ★ 屏幕不亮 / 全黑的排查（最常踩的坑）

### 2.1 先看开机日志

`bsp_display_init()` 严格按这个顺序执行，日志会一步步打出来：

```
I (xxx) roll_coater:  Reset reason: POWERON (正常上电)
I (xxx) roll_coater:  Board   : JC8048W550 / ESP32-8048S050 (PCLK=GPIO42)
I (xxx) roll_coater:  Panel   : 800x480 RGB565 parallel, BL=GPIO2
I (xxx) bsp_display: Backlight ON                       <- 背光最先亮
I (xxx) bsp_display: Init RGB panel 800x480 @ 18MHz, PCLK=GPIO42, BL=GPIO2
I (xxx) bsp_display: RGB panel ready (num_fbs=1, bounce=32000 px = 64000 B x2 in internal DMA RAM)
I (xxx) bsp_display: Panel scan 43.9 Hz (PCLK 18MHz / 410000 px per frame)
I (xxx) bsp_display: Both frame buffers pre-filled with 0xFFFF
I (xxx) bsp_display: Display mode: partial + bounce | LVGL 20 lines x2 = 64000 B in INTERNAL RAM
I (xxx) bsp_display: LVGL refresh auto-set: 34 ms (29.3 Hz) vs panel 43.9 Hz
I (xxx) bsp_display: Panel self-test: filled 0xFFFF (screen should be light)   <- 整屏刷白
I (xxx) bsp_display: LVGL display registered
I (xxx) bsp_display: Touch I2C: SDA=19 SCL=20 @100000Hz
I (xxx) bsp_display: GT911 found at 0x5D
I (xxx) bsp_display: Touch input registered
```

> ⚠️ **中文显示成乱码（例如 `姝ｅ父涓婄數`）= 串口工具的编码没设成 UTF-8**，不是固件问题。
> 固件日志一律输出 **UTF-8**；串口助手要选 `UTF-8`（不要 GBK / ANSI），
> 或直接用 `idf.py -p COMx monitor` + Windows Terminal / VS Code 的 UTF-8 终端。
> 判断特征：**同一份日志里英文正常、只有中文乱码**（2026-09-22 现场遇到过，
> 当时被误判成"界面乱了"）。串口工具里敲 `mtest` / `help` 这类纯 ASCII 命令不受影响。

关键设计：**背光在所有可能失败的初始化之前点亮**，且 `app_main` 里**不用
`ESP_ERROR_CHECK`**（失败只打印并停住，不 abort 重启）。所以：

| 现象 | 结论 | 处理 |
|---|---|---|
| 屏幕**完全没光**、日志停在 `Backlight ON` 之前 | 背光/供电/引脚问题 | 查 BL 是否 GPIO2、屏排线、5V 供电 |
| 有光、**先白一下再黑**，日志有 `Panel self-test` | 面板通路 OK，是 LVGL 注册显示失败 | 看日志 `lvgl_port_add_disp_rgb failed` 后面那行 |
| 有光、**一直黑**，日志有 `Panel self-test: filled 0xFFFF` | 面板收不到像素时钟 / 数据线恒 0 | **板型（PCLK）选错**，见 2.3 |
| 有光、**能出图但抖动/花屏/偶发横带** | 实时通路断流，或 LVGL 与 bounce 抢同一块帧缓冲 | 见 **2.5** |
| 有光、**只有某个大色块在闪**（绿色 Enter 键最典型） | 面板帧率偏低导致的液晶闪烁 | 见 **2.6** |
| 有光、**颜色不对（红蓝互换）/ 画面偏移** | 数据线极性、色序或消隐区不对 | 红蓝互换改 `CONFIG_LV_COLOR_16_SWAP`；偏移调 `bsp_pins.h` 的 HSYNC/HBP/HFP 与极性 |
| 日志**反复重新开始**（Reset reason 一直是 PANIC/TASK_WDT） | 有崩溃 | 用 `idf.py monitor` 看 backtrace |

### 2.2 复位原因对照

`Reset reason` 由 `main.c` 的 `reset_reason_str()` 打印：

- `POWERON` 正常上电
- `PANIC` 崩溃（异常）—— 看 backtrace
- `TASK_WDT` 某任务卡死（常见于 LVGL 任务里做了阻塞操作）
- `INT_WDT` 中断里耗时太长
- `BROWNOUT` 供电跌落（USB 线/电源电流不够，RGB 屏背光很吃电流）

### 2.3 ★ 板型 / PCLK 必须选对

`bsp_pins.h` 有两套预设，**只有 PCLK 与触摸 RST 不同**：

| 功能 | JC8048W550（默认） | CrowPanel 5.0 |
|---|---|---|
| PCLK | **GPIO42** | **GPIO0** |
| GT911 RST | GPIO38 | NC（板上未引出） |
| 背光 BL | GPIO2 | GPIO2 |
| VSYNC / HSYNC / DE | 41 / 39 / 40 | 41 / 39 / 40 |
| 数据线 DATA0..15 | 8,3,46,9,1, 5,6,7,15,16,4, 45,48,47,21,14 | 同上 |
| 触摸 SDA / SCL | 19 / 20 | 19 / 20 |

**PCLK 选错的典型现象：背光亮、整屏全黑**
（面板拿不到像素时钟 → 数据线一直输出 0 → 黑）。

切换方式：

```bash
idf.py menuconfig
  -> Roll Coater HMI 配置 -> 目标板型
```

**PCLK 由 `CONFIG_ROLLCOATER_LCD_PCLK_MHZ` 统一决定（默认 18MHz ≈ 43.9Hz），
两块板共用同一个值**，切板型不需要再动它：

```bash
idf.py menuconfig
  -> Roll Coater HMI 配置 -> RGB 面板像素时钟 PCLK (MHz)
```

**LVGL 刷新周期不用手工配。** `bsp_display.c` 会在运行时把
`disp->refr_timer->period` 设成"面板帧周期 × (1 + `BSP_LVGL_SLOWDOWN_PCT`%)"，
所以 sdkconfig 里的 `LV_DISP_DEF_REFR_PERIOD` 只是个初值、会被覆盖 ——
改 PCLK 后**不要**再去手工同步它。开机日志会同时打印两者：

```
I bsp_display: Panel scan 43.9 Hz (PCLK 18MHz / 410000 px per frame)
I bsp_display: LVGL refresh auto-set: 29 ms (34.5 Hz) vs panel 43.9 Hz
```

| `ROLLCOATER_UI_PUSH_MS` | 100 | 位置推送到 UI 的周期（规范要求 1000） |

### 2.5 画面抖动 / 花屏 / 闪 —— 三条约束

RGB 并口屏 + PSRAM 帧缓冲要同时满足三个约束，任何一条被破坏都会表现为
**抖动 / 花屏 / 闪**：

**① 实时通路不能断流**
800×480 RGB565 @43.9Hz 要求 GDMA 稳定吃掉 ≈33.7MB/s（@29.3Hz 是 22.5MB/s）。
帧缓冲在 PSRAM，bounce buffer 的重填是 **GDMA EOF 中断里的一次 PSRAM memcpy**
（`esp_lcd_panel_rgb.c` 的 `lcd_rgb_panel_fill_bounce_buffer`）。
PSRAM 通路一被挤占，中断里的 memcpy 晚一点，DMA 就断流 → 横向抖动/花屏。
所以 PCLK 不是越高越好：搬运总量 = 全屏字节 × 帧率，18MHz 时 CPU 已经要花 40% 左右。

**② LVGL 写帧缓冲、bounce 读帧缓冲，两者不能撞车（★ 最容易踩的一条）**
`rgb_panel_draw_bitmap()` 永远写 `fbs[cur_fb_index]`，而 bounce 引擎从
`fbs[bb_fb_index]` 读。普通局部刷新模式下这两个索引**恒等于 0**、就是同一块内存，
于是 LVGL 写到一半的脏区会被 bounce 直接搬上屏 —— 现象是
**偶发一条"半新半旧"的横带**，而且 PCLK 越高、LVGL 写 fb 越频繁，撞得越多。

处理：**现在的默认是方案 A（`PARTIAL_BB`）** —— 单 fb + bounce，DMA 只读内部 RAM，
画面**不会整屏错位**，代价是上面那条偶发横带（用 `BSP_LVGL_SLOWDOWN_PCT` 压）。
> ★★ **2026-09-22 深夜现场结论：方案 B（`AVOID_TEARING`）不能作默认。** ★★
> 它的设计意图正是消除这条横带（双 fb、LVGL 画后台 / bounce 读前台），
> 但本板实测的后果严重得多：**所有界面**都出现"控件错位 / 只画了一半 / 局部还是旧内容"
> —— 因为 LVGL 只把**脏区**画进后台 fb，没被重画过的区域就一直留在屏上。
> 现场口径是"**显示屏的界面乱了**"（每个界面都乱，不是某一页的代码问题）。
> ⇒ 退回方案 A。要再验证 B 就把 `bsp_display.c` 的 `BSP_LVGL_DISPLAY_MODE` 改回去，
> 并**先拍照留证**。

**③ 不该重绘的时候绝不要重绘**
`lv_label_set_text()` 内部是**无条件** `lv_obj_invalidate()`（即使文字没变），
`lv_obj_set_style_xxx()` 也会刷新样式。而运动任务每 100ms 就推一次位置，
如果照单全收地写进 label，静置画面也会变成每秒 ~10 次
「同一内容重绘 → 往帧缓冲搬运」，搬运瞬间撞上面板扫描就是**闪一下**。

工程里已经按这三条做了处理，出问题时按下面顺序排查/加余量：

| 顺序 | 手段 | 现在的值 | 说明 |
|---|---|---|---|
| 1 | 文本/样式只在变化时才写 LVGL | 已做（`ui_main.c` 的 `main_set_text_cached`） | 静置时零重绘，先排掉软件侧抖动 |
| 2 | **单 fb + bounce（方案 A，★ 现在的默认）** | `BSP_LVGL_DISPLAY_MODE = PARTIAL_BB` | **画面不会整屏错位**（DMA 只读内部 RAM）；代价是偶发一条横带闪 |
| 3 | 压低 LVGL 写 fb 的频率 | `BSP_LVGL_SLOWDOWN_PCT = 50`（原来 25，改成 100 最干净） | 写 fb 次数变少 → 撞上②那条竞争的机会变少（只能减少，不能根除） |
| 4 | LVGL 绘制缓冲放内部 RAM | `buff_spiram = 0` | 渲染不占 PSRAM 通路，bounce 的补数 memcpy 不会被挤晚 |
| 4b | ~~双 fb + bounce（方案 B `AVOID_TEARING`）~~ | **已退回，不要用** | 本板实测会让**所有界面**"控件错位/只画一半/局部是旧内容"，见上面的现场结论 |
| 5 | 降 PCLK | 18MHz（默认） | 从 24MHz 往下降能加余量；出现抖动/花屏先降它 |
| 6 | 关掉 `CONFIG_LCD_RGB_RESTART_IN_VSYNC` | **已关** | 它每 VBlank 重置一次 GDMA 通道，已稳定的板子上会反而变成"每帧轻轻一眨" |
| 7 | 加大 bounce buffer | 40 行 = 64KB ×2 | `BSP_LCD_BOUNCE_BUFFER_HEIGHT` 要能整除 384000 字节（40/48/60 都行）；48 行以上内部 RAM 会不够 |
| 8 | 排线/供电 | — | 5 寸屏排线长、背光耗电大，USB 供电不足也会周期性闪 |

> ★ 千万不要在 `num_fbs=1` 时去掉 bounce buffer：那样 LVGL 写的就是 DMA 正在
> 连续扫描的唯一帧缓冲、而且毫无同步，画面会大面积撕裂/错位（实测"显示全乱"）。

### 2.6 只有某个大色块在闪 = 面板帧率偏低（液晶闪烁）

现象：画面内容没变，但**屏幕上某一个颜色块**在轻微闪烁，其他区域看着正常。
最典型的是主屏那个**绿色 Enter 键**。

原因：`UI_C_KEY_ENTER = 0x2E7D32` 转成 RGB565 是 `(5, 31, 6)` —— 绿子像素
**31/31 满量程**，对应的液晶单元驱动电压最大、帧间电荷漏电也最明显，所以它是
整屏里第一个把"帧率不够"暴露出来的色块。对比 STOP 的红色是 26/31、
#EEEEEE 背景更接近中值，就都不容易被看出来。

**这不是 bug，是面板帧率低于它的设计值**（800×480 这类屏通常按 60Hz 设计）。
处理办法只有一个 —— **提高 PCLK**：

| PCLK | 扫描率 | 效果 |
|---|---|---|
| 12MHz | 29.3Hz | 满量程色块能看到明显闪烁 |
| **18MHz** | **43.9Hz** | ✅ 默认值，闪烁基本不可见 |
| 20MHz | 48.8Hz | 还可以试，接近安全边界 |
| 24MHz | 58.5Hz | 帧率最舒服，但 bounce 补数只剩 ~30% 余量、CPU 搬运 >55%，容易反而变抖 |

> 别指望用 LVGL 刷新周期去治它：面板是自由扫描的，像素多久被重写一次只由
> 扫描率决定，调 `BSP_LVGL_SLOWDOWN_PCT` 对这类闪烁毫无作用。
> 另外"整屏偶尔一条横带"是 2.5 的②（写读竞争），和这里的色块闪烁是两回事。

### 2.7 切换到 AXS15231 触摸

## 3. 任务与线程模型

| 任务 | 优先级 | 干什么 |
|---|---|---|
| `lvgl_port` 任务 | 4 | `lv_timer_handler()`；**UI 全部在这里跑** |
| `motion` | 5 | 消费目标位置队列、积分梯形曲线、RMT 发脉冲、报警停机 |
| `cfg_save` | 3 | 参数异步落盘（NVS 写不在 UI 线程里做） |

- **LVGL 任务里禁止 >10ms 的阻塞操作**。UI 只做三件事：
  1) 从 `app_motion` 的环形队列取位置（非阻塞）
  2) 从 `app_state` 的事件队列取事件（非阻塞）
  3) 更新 label / 背景色
- 定时器：`ui_main` 里的 50ms 轮询（位置+事件+背景色）、100ms 长按检测。
- 三个屏幕（主菜单 / MOTOR TEST / Admin）之间用 `lv_scr_load()` 切换；
  弹窗挂在 `lv_layer_top()`，所以换屏（比如点返回键回主菜单）不会把报警窗弄丢。
  定时器是全局的：即使切到主菜单，`ui_main` 的 50ms 轮询照旧在跑
  （这样再进 MOTOR TEST 时读数是最新的），所以那些刷新都做了"值不变就不写"的缓存。

## 4. 状态机

```
State1 ──Enter 且值在限内──> State2 ──Enter 且值在限内──> 下发运动 (motion_task)
  │                            │
  │ Enter 且值越限             │ Enter 且值越限
  ↓                            ↓
State3                      提示行红字 Out of range，**留在 State2**
  │                         （★ 不弹窗、不进 State3、背景也不会变橙）
  │ 弹窗1「Was the entered value typed correctly?」
  ├─ No  -> 回 State1（清空输入缓冲区）
  └─ Yes -> 弹窗2「Manually move the axis ... then press Enter.」
            ├─ 再提交仍越限 -> 弹窗2 带上下限重新提示，留在 State3
            └─ 再提交在限内 -> State2（与 State1 的成功分支相同：标定当前位置）
```

> **State3 只能从 State1 越限进入**，这是测试时最容易搞错的一点：进了 State2 之后
> 再输越限值只会被拒绝，看不到橙背景、也没有弹窗1 可点。
> 而 State1 的「限内成功」和「越限进 State3」这两条分支要分两次测 ——
> 进 State2 之后需要**复位**，或者从 State3 点 `No` 退回 State1。

- **背景色**：`|current − target| ≤ 0.005` → 整屏绿 `#2E7D32`；运动中 → 整屏红
  `#D32F2F`；越限待确认 → 橙 `#F9A825`；位置未标定（开机） → 浅灰 `#EEEEEE`。
- **Admin 入口**：State1/State2 下输入 `9.999` 并**长按 Enter 满 3 秒**。
  实现：Enter 按钮的 `LV_EVENT_PRESSED/RELEASED` 记录时间戳，100ms 定时器判定；
  长按优先——那一次 Enter 不会再被当成普通提交（`s_admin_consumed` 吞掉点击）。
- **Admin 退出**：`Exit and Accept` → 异步写 NVS → 回到 State1 并要求重新标定
  当前位置（限位可能已改，坐标系作废）。
- **报警**：ALARM 输入**本工程已关闭**（`MOTION_GPIO_ALARM = -1`，现场驱动器没有报警输出）。
  代码逻辑仍在（中断 + 电平轮询双判定、锁存后抬 ENA、弹全屏红窗、`ACKNOWLEDGE` 时
  若引脚仍有效则拒绝清除），只是没有输入源。要启用就把它改成一个空闲脚。
  ⚠️ 别去短接 IO13 —— 它现在是 ENA 输出脚。
- **使能（ENA/IO13）随状态切换**：State1 / State3 输出**高 = 脱机**（操作员要手动盘轴、
  读刻度盘）；**State2 一进入就拉低使能，并在整个停留期间保持低**（不是"等发脉冲时才拉低"）。
  与参考工程 `app.cpp:153-163` **逐状态对齐**（`case ST_CALIB: motor_set_enabled(false);`
  / `case ST_TARGET: motor_set_enabled(true);`）。
  ★ 依据（2026-09-22 现场定稿）：实测"**把 IO13 强制拉低，电机就正常了**" ⇒ ENA 这一路
  必须是**稳定的低**；原来只有 `motion_begin()` 才拉低、而 `run`/上电固定段跑完还会主动抬
  ENA 脱机，所以"进 State2 之后到下一次运动之间"驱动器是失能的，现场现象就是随机失步
  （"正转反转 / 一顿一顿 / 有时能转有时不能"）。接线与共地判据见 9.9。

### 5.0 「正在输入」的显示规则（界面稿里没有，因为稿子是静态图）

读数卡片**永远**显示一个数值，输入缓冲区是"盖在卡片上"的临时值：

| 情况 | 显示 | 颜色 | 边框 |
|---|---|---|---|
| State1 / State3 正在键输入 | 输入缓冲区（你按的数字） | **蓝色** `#1565C0` | 绿色粗 |
| State2 正在键输入 | 输入缓冲区 | **蓝色** | 绿色粗 |
| 没有输入（或刚被清空 / 提交完） | State1：实际位置；State2：已提交的目标 | 当前值绿 `#2E7D32` / 目标值黑 `#212121` | 常规灰 |

所以"输入被清空"在屏幕上的表现是：**蓝色数字变回绿/黑，粗边框消失**，
而不是数字变空白或归零 —— 卡片上永远会有一个值。
如果清空后显示的数值恰好等于你刚才输入的值（例如你输入的就是已提交的目标），
那画面确实看不出变化；这时按任意一个数字键即可验证：缓冲区是从空开始拼的
（空缓冲按 `5` 应显示 `0.005`，若显示 `<原值>5` 才说明真的没清干净）。

#### 5.0.1 ★ 键盘输入规则：敲进去的数字要 ÷1000

键盘**没有小数点键**。缓冲区里存的是"去掉小数点的那个整数"，提交时才除以 1000：

```c
float ui_entry_value(const ui_entry_t *e)
{
    ...
    /* 缓冲区是纯数字，除以 1000 得到 3 位小数 */
    return (float)strtoul(e->buf, NULL, 10) / 1000.0f;   /* ui_numpad.c */
}
```

所以**要输入 `X.XXX`，就得依次敲 `X.XXX` 去掉小数点后的那几位**：

| 想要的数值 | 要敲的键 | 备注 |
|---|---|---|
| `0.005` | `5` | 从最右边一位开始填 |
| `0.099` | `9` `9` | ⚠️ **不是 99.000** |
| `0.500` | `5` `0` `0` | 低位自动补 0 |
| `12.000` | `1` `2` `0` `0` `0` | |
| `45.000` | `4` `5` `0` `0` `0` | |
| `99.000` | `9` `9` `0` `0` `0` | 测越限要用这个 |
| `9.999` | `9` `9` `9` `9` | Admin 解锁值 |

约束（见 `ui_entry_push_digit()` / `UI_ENTRY_MAX_DIGITS`）：

- 最多 **5 位**，也就是能表达的最大值是 `99.999`
- **满 5 位后新敲的数字会被丢弃，而缓冲区不会自动清空** —— 连续输入多组数时
  （例如先敲 `5000` 再敲 `99000`）得到的是 `50009`（=50.009），不是 `99000`。
  **换一组数之前先按 `⌫` 清掉。** 丢弃时日志会打
  `entry buffer full (5 digits), key 'x' dropped`
- **首位不能是 `0`**（首位敲 `0` 会被忽略）→ 想要 `0.099` 就敲 `99`，不要敲 `099`
- 缓冲区为空时按 Enter 视作 `0.000`

> 这就是为什么测限位不能敲 `99`：那输入的是 `0.099`，落在 [0, 50] 里，会被
> 正常接受并当成标定值（当前值、目标值都会变成 0.099）。想触发"越限进 State3"
> 必须敲 `99000`。日志里每笔提交都有记录，可以直接对照：
> ```
> I app_state: Submit 99.000 in State 1 (limits 0.000 .. 50.000) OUT-OF-RANGE
> I app_state: Submit 0.099 in State 1 (limits 0.000 .. 50.000) OK
> ```

### 5.1 字体：为什么是 Lato Bold

界面稿所有文字都是粗体，而 LVGL 内置 Montserrat 只有 Regular。所以工程挂了
4 个真粗体字库（源文件在 `main/fonts/`，LVGL 8/9 双兼容格式）：

| 变量 | 字号 | 实测量形高 | 用途 |
|---|---|---|---|
| `ui_font_H1_bold` | 50px | 36px | 主屏读数大数字 |
| `ui_font_H2_bold` | 44px | 31px | 数字输入页的大数字 |
| `ui_font_H3_bold` | 35px | 25px | 键面数字、STOP、Admin 参数值 |
| `ui_font_P1_bold` | 25px | 18px | 标题 / State / 提示行 / 卡片小标题 / Admin 参数名 |

> ⌫ / ↵ 是 LVGL 符号字形（U+F0xx），Lato 字库不含，所以这两个键用内置
> `lv_font_montserrat_32`（见 `UI_FONT_SYMBOL`）。

**换成 Montserrat Bold / 更大的读数字体**（可选，需要 node + npm）：

```bash

npx lv_font_conv --font Montserrat-Bold.ttf --size 64 --bpp 4 --format lvgl \
    -r 0x20-0x7F --no-compress \
    -o main/fonts/ui_font_H1_bold.c

# 其余三个同理：44 / 35 / 25
```

只要**文件名和变量名不变**，覆盖后代码一行都不用改。
（本机没有 node，所以现在用的是从
`examples/get-started/squareline_coffee_5inch/main/ui/fonts/` 拷来的 Lato Bold。）

>
> ★ **v15（同日深夜）：曲线起步那一下** —— 关软启动后**第一拍就是巡航频率**（不再是
> "先 8500 再爬"，那正是现场质疑的"你这不是 12000Hz 吧"）。详见 **9.12.7.1**。
>
> ★ **v9 的另一半：波形 + 上电自证**（同一天）
> 现场反馈"按 v8 还是不转"，于是把最后两个没与例程对齐的变量一起对齐 ——
> ① **STEP 脉宽默认 `5µs` → `0`（50% 方波）**，与能转的例程波形一致（`ROLLCOATER_STEP_PULSE_US`）；
> ② 新增 **上电固定段**：上电先跑「使能→DIR→20ms→**8500Hz 连发 10 秒**→停+脱机」，
> 与例程上电段逐项同构（`ROLLCOATER_BOOT_HOLD`，默认开；`mtest hold [hz] [ms]` 可复跑）。
> 详见 **9.12.5**。
>
> ⚠️ v6 那两个值（1mm/s / 4mm/s²）在这台机器上是**"不动"而不是"慢"** ——
> 800Hz 落在低频禁区里。v7 把它们改回来但选了未验证的 16000Hz；
> **v8 换成现场唯一被直接验证过的 8500Hz**，同时给曲线加了**起跳频率下限**
> （`MOTION_TURN_FREQ_MIN_HZ`）。
>
> 换固件后 **NVS 里的旧值会盖掉新出厂值**，所以加了 `fac_ver` 迁移机制：
> 固件启动时发现 NVS 里的版本更旧，就**只把 `speed/accel/decel` 强制刷成新出厂值**，
> **限位 / 位置 / 反向间隙一律不动**（已标定的坐标系不受影响），
> 不需要 erase-flash、也不需要进 Admin 手工改。
> 以后每次调出厂默认值，把 `app_config.c` 的 `APP_CFG_FACTORY_VERSION` +1 即可。
> 日志：`出厂参数升级 v1 -> v2：Speed/Accel/Decel 重置为出厂值（限位/位置/反向间隙保持不动）`。
> 开机日志 `Config loaded: ... speed=... accel=...` 打的是**真正生效**的值。

写盘走 `app_config_commit_async()`（队列深度 1、覆盖式 + 独立任务），
UI 线程只做一次入队，不碰 flash。

### 6.1 上电行为（★ 最容易困惑的一点）

| 项目 | 上电后 | 实现位置 |
|---|---|---|
| 7 个参数 | **保留上次的值** | `app_config_init()` 从 `rc_hmi` 读 |
| 两个读数卡片上的数字 | 显示**上次保存的 `pos`**（不是 `0.000`） | `app_state_init()` 的 `s_target = cfg.pos`，motion 也用同一个值初始化当前位置 |
| 状态机 | **强制回 State1** | 不持久化 |
| 是否已标定 | **强制"未标定"**（背景浅灰、提示 `Enter Roll Coat Height`） | `s_pos_known = false` |

设计意图：参数（限位 / 加减速 / 速度 / 背隙）必须保留，否则现场每次上电都要重新配；
但**"当前位置"不可信** —— 断电期间轴可能被人手轮动过，所以上电一定要由操作员
重新输入刻度盘读数来标定坐标系。

同理，这两处也会回到"未标定 + State1"：

- 报警 `ACKNOWLEDGE` 之后（`app_state_ack_alarm()`）
- Admin `Exit and Accept` 之后（`app_state_exit_admin()`，限位可能已改，坐标系作废）

> ⚠️ 所以**读数卡片上出现数字 ≠ 输入缓冲区有内容**。缓冲区空不空只看颜色和边框
> （见 5.0 节）。上电后卡片上的 `30.000` 之类是上次的位置，不是你上次的输入残留；
> 想让它归零就把 NVS 擦掉（`idf.py erase-flash`）或从 Admin 里把 `Current Position` 改成 0。

## 8. 与原始规格的差异（都是有意为之，别再改回去）

需求里给过两轮界面要求，第一轮是文字规格、第二轮是界面稿（附图）+「浅色主题」。
两者在几处冲突，最终**以界面稿为准**；另有几条是实现时的主动增强。这里逐条记下来，
免得以后照着旧规格"纠错"把已经调好的东西改坏：

| 原始规格 | 现在的实现 | 依据 / 原因 |
|---|---|---|
| 卡片 `x=16 y=72 w=372 h=130` | `x=15 y=63/215 w=362 h=138` | 界面稿解码成像素矩阵后实测出来的（见第 5 节） |
| 键盘 `x=420 y=72`，键 `112×68` | `x=400 y=104`，键 `120×64` | 同上 |
| STOP `x=420 y=380 w=364 h=64` | `x=400 y=400 w=384 h=56` | 同上 |
| 顶栏 `h=48` | 白底 0..46 + 2px 分隔线 47..48 | 同上 |
| **键盘上方"输入框"显示缓冲区（0.000 格式）** | **没有独立输入框**：缓冲区直接盖在读数卡片上（蓝字 `#1565C0` + 绿色粗边框） | ① 界面稿里键盘上方那行是**提示行**，同一个位置冲突；② 盖在卡片上时"正在输入的是哪个值"更直观（State1/3 盖当前值卡片、State2 盖目标值卡片） |
| **底部提示行 `y=452 h=24`** | 未实现；提示行在键盘正上方 `y=65` | 界面稿要求"键盘正上方提示行" |
| 深色主题 `#1A1A2E`、卡片深色底 | 浅色主题，页面 `#EEEEEE`、卡片白底 | 第二轮要求"浅色主题" |
| 每秒向 UI 推送位置 | `ROLLCOATER_UI_PUSH_MS = 100` | 运动读数平滑爬升；改回 1000ms 会一秒才跳一次，一顿一顿 |
| 上电第一屏 = 辊涂机主屏 | 上电第一屏 = **主菜单**（5 张卡片），辊涂机主屏变成 `MOTOR TEST` 子界面 | 界面稿 `ui1_main.png` 画的就是主菜单（LIGHT / ENVIRONMENT / MOTOR TEST / HISTORY / SETTINGS），`ui2_light.png` 画的是"左上返回键 + 标题"的子页 —— 本来就是两级结构 |
| （界面稿里没有子页返回键） | MOTOR TEST 顶栏左上角加了圆形 `‹` 返回键，标题从 x=16 挪到 x=56 | 主菜单是 MOTOR TEST 的父级，必须有回去的入口；样式沿用 `ui2_light.png` 的返回键（白底圆 + 蓝描边 + ‹） |
| （界面稿里没有手势） | 加了「从右向左滑动 = 返回主菜单」 | 需求明确指定的返回手势方向（`LV_DIR_LEFT`） |
| LIGHT / ENVIRONMENT / HISTORY / SETTINGS 只有卡片 | 卡片照界面稿画出，点击弹 `xxx not available yet` 提示条 | 需求只确认了 MOTOR TEST 一个入口；不做"点了没反应"的死界面 |
| 主菜单顶栏的信号格 / 时钟 / 卡片摘要 | 信号格与摘要文案是**静态占位**（没联网、没接传感器）；时钟没设时间时显示 `--:--` | 界面稿要求有这些元素，但工程里没有对应的数据源；先照稿画出并明确标注，避免以后把它们当成"坏掉的实时数据" |
| （规格未提） | 上电后、报警 `ACKNOWLEDGE` 后、Admin `Exit and Accept` 后，都回到 State1 并要求**重新标定** | 这三处坐标系都可能失真：断电期间轴可能被手轮动过、限位可能被改。规格里 State1 就是"输入刻度盘实际位置"，等于上电本来就要做这一步 |
| Speed/accel/decel 出厂默认 `20mm/s`、`150mm/s²` | **`20mm/s`、`60mm/s²`**，并用 `fac_ver` 迁移机制强制生效 | 2026-09-22 现场"电机只嗡嗡响不转圈"：调试期用过 2mm/s、10mm/s，最终按现场参考波形（15.5kHz / 20mm/s）回到 20mm/s，只把 accel 从 150 降到 60 更温和；真正的原因不是频率（扫频证明 16kHz 也能转），见 9.7 |
| （规格未提） | 上电**可**跑一次**频率扫描自检**（`ROLLCOATER_MOTION_SELFTEST`，现已**默认关闭**） | 现场需要"一次烧写就测出机械步频上限"。行程 1.75mm 自动退回；因为每次上电都会动一下，所以只在排障时打开（见 9.7） |
| 报警引脚 `ALARM`（旧文档 IO17 / IO13） | **`-1`（整段关闭）** | 现场驱动器没有报警输出；且 IO13 已被 ENA 占用。要演练就填一个空闲脚（IO17/IO18/IO10）再短接那根 |

> 判断"输入缓冲区是否为空"只看**颜色和边框**：
> 蓝字 + 绿色粗框 = 有内容；绿/黑字 + 常规灰框 = 已空。
> **不要看卡片上有没有数字** —— 卡片永远显示一个数值（见 5.0 节），
> 上电时显示的是上次保存的位置（见 6.1 节）。

## 9. 硬件接线

### 9.1 引脚一览

| 功能 | GPIO | 方向 | 有效电平 | 说明 |
|---|---|---|---|---|
| STEP | **11** | 输出 | 上升沿有效 | RMT 生成，40Hz ~ 20kHz |
| DIR | **12** | 输出 | 目标增大时 = **高** | 反向 = 低 |
| ENA | **13** | 输出 | **低有效**（低 = 使能） | State1/State3 输出**高**（脱机，便于手动盘轴）；State2 拉低使能 |
| ALARM | **-1（关闭）** | — | — | 现场没有报警信号源，整段关掉（与参考工程一致）。要启用就填空闲脚（IO17/IO18/IO10） |

### 9.2 接步进驱动器

**A. 模块类（DRV8825 / TMC2209 / A4988）—— 3.3V 兼容，直连即可**

```
GPIO11 ──→ STEP          (PUL)
GPIO12 ──→ DIR
GPIO13 ──→ EN / nEN      低有效，和本工程 MOTION_ENA_ACTIVE_LEVEL=0 一致
GND    ──→ GND           ★ 必须共地
驱动板 VMOT/GND ──→ 电机电源（8~36V，按模块规格）
```

**B. 工业驱动器（TB6600 / DM542 / DM556）—— 光耦输入，通常是 5V 规格**

```
共阴接法（本工程按这个设计，推荐先试这个）：
  GPIO11 ──1kΩ──→ PUL+
  GPIO12 ──1kΩ──→ DIR+
  GPIO13 ──1kΩ──→ ENA+
  ESP32 GND ────→ PUL- / DIR- / ENA-
```

两个坑：

- **3.3V 直驱这类驱动器的光耦不保证可靠**（光耦一般要 5~15mA，3.3V 串 1kΩ 只有约 2mA）。
  电机不动就先把电阻减到 470Ω→330Ω；还不行就上 74HCT245（VCC=5V）做电平转换，或直接用光耦隔离模块。
- **STEP 步频 = speed × 步数每毫米**（见 9.5，默认 800）：出厂 `speed=2mm/s` → 1600Hz；
  调到 10mm/s 就是 8kHz。步频越高，对光耦与驱动器 PUL 上限的要求越高。
  普通 PC817 光耦的上升/下降时间是几十 µs，**跟不上 (kHz 以上) 的窄脉冲**，
  必须用 6N137 这类高速光耦，或纯电平转换。TB6600 / DM542 板载的通常是高速光耦，可以用。

#### 9.2.1 ★ TB6600 + 42 步进「只嗡嗡响不转圈」专查（2026-09-22 现场）

**① 先用"手动点脉冲"把固件彻底排除（1 分钟，最有价值）**

1. TB6600：`PUL- / DIR- / ENA-` 接 GND（共阴）；`ENA` 先不接（悬空 = 使能）。
2. 从控制侧取 **+5V**，串一根线接到 `PUL+`；用手把这根线在"接上 5V / 断开"之间
   以 **1~2 次/秒**的节奏反复点。
3. 判读：
   - 电机**一步一步跟着点地转** → 驱动器/电机/电流/相序都没问题，

   - 只听到咔咔声 / 原地抖动 → **与频率、与任何固件都无关**，看 ③④⑤。

若你接的是共阳（`+` 端接 5V、`−` 端接 IO11/12/13），逻辑会整体反相 ——
DIR 会反、ENA 的使能/脱机会颠倒，表现为"方向不对/时转时不转/只震不转"。
**判据：用万用表量 `PUL- / DIR- / ENA-` 是不是都接到了 ESP32 的 GND。**

> 落在低速共振区），两个因素一起就是"空载也原地来回微抖"。

> （必须把 `ROLLCOATER_STEPS_PER_UNIT` 改成 400，否则软件按两倍速度发脉冲，
> 0.5A 下起步就堵转 = 只嗡嗡不转）。

**④ 电机类型必须确认（★ 最容易搞错的一条）**

`42BL…` 这个命名**两种都有人用**：
- **两相步进**：4 根引出线（6/8 线的也能两两配对成两组线圈），组内电阻几 Ω，
  **两组之间互不导通** → 可以用 TB6600；
- **三相无刷 BLDC**：**3 根粗相线（U/V/W）+ 5 根细霍尔线**，任意两相之间电阻相近
  （星形/三角形网络）→ **TB6600 是两相步进驱动器，根本驱动不了它**，
  现象就是"嗡嗡震动不转圈"，换什么固件都一样，必须换 BLDC 驱动器。

**⑤ 其他硬条件**：ESP32 GND 与 TB6600 信号 GND **必须共地**；
TB6600 电源 9~42V 且电流 ≥ 电机额定 × 1.5（欠压/欠流会触发限流关断 = 抖动）；
电机相序按 `A+ A−`、`B+ B−` 分成两组接（接错也能转但噪音大、力矩小，
只接一相则只会原地抖动）。

### 9.3 ALARM（本工程已关闭）

现场这块驱动器没有报警输出，所以 `MOTION_GPIO_ALARM = -1`，相关代码整段被编译掉 ——
**不需要接任何线**。开机日志会打：

```
W app_motion: ALARM input DISABLED (MOTION_GPIO_ALARM = -1): no alarm source wired
```

这样同时也修掉了"**没接报警却一直报 ALARM**"：旧引脚下代码把 IO13 当报警输入读，
而现场 IO13 是 ENA，驱动器把 ENA 拉低使能 → 被读成低电平 → 误判报警。

以后要接报警输入时：

```
驱动器 ALM / FAULT 输出 ──→ （先把 MOTION_GPIO_ALARM 改成一个空闲脚，如 IO17）
                              ├─ 4.7kΩ 上拉到 3.3V（内部上拉很弱，长线建议外加）
                              └─ 100nF 到 GND（抗干扰）
```

- ★ **驱动器 ALM 若是 24V 电平，绝对不能直接接 GPIO**（会烧脚），必须经光耦或分压。
- 演练：把该脚短到 GND 即触发（模拟模式下也有效）。
- ⚠️ **★ 绝不要短接 IO13 演练报警**：它现在是 ENA **输出脚**，短接可能损伤引脚。

### 9.4 电源

- ESP32 + 5 寸屏：**5V / ≥2A**。背光很吃电流，USB 口供电不足会 `BROWNOUT` 复位。
- 步进驱动器：独立电源（按电机选 24/36/48V），**必须与 ESP32 共地**，否则 STEP/DIR 没有参考电平。
- 电机动力线与信号线分开走，避免电机回路噪声串进 STEP。

### 9.5 ★ 机械参数必须按实际改

**改这里**（2026-09-22 晚起从写死的宏改成 menuconfig 项）：

```
menuconfig -> Roll Coater HMI 配置 -> 每毫米脉冲数 Steps per unit（默认 800）
```

它等价于 `app_motion.h` 里的 `MOTION_STEPS_PER_UNIT`，是**位置换算的唯一依据**：
`脉冲数 = 位置(mm) × 本值`。**填错的话位置与速度都会差一个倍数**（不是"不转"）。

算法：**驱动器脉冲/圈（拨码决定）÷ 丝杠导程(mm)**

| 电机 | 脉冲/圈（拨码） | 丝杆导程 | steps/mm |
|---|---|---|---|
| 1.8°（200 步/圈） | 3200（16 细分） | 4mm | **800（默认）** |
| 1.8° | **1600（8 细分，厂商口径）** | **2mm** | **800** ✅ 与默认自洽 |
| 1.8° | **1600（厂商口径）** | **4mm** | **400** ★ 必须改成 400 |
| 1.8° | 1600 | 5mm | 320 |
| 1.8° | 3200 | 5mm | 640 |
| 1.8° | 3200 | 2mm | 1600 |
| 1.8° | 6400（32 细分） | 4mm | 1600 |

★ **别猜，量出来最快**（不需要知道导程和细分）：

```
打开 ROLLCOATER_MOTION_SELFTEST（见 9.7 第 2 步）：
每档固定 200 步 -> 量出实测位移 d (mm) -> 真实 steps/mm = 200 / d
    d = 0.25mm  -> 800
    d = 0.50mm  -> 400     （说明驱动器是 8 细分 + 4mm 导程）
    d = 0.125mm -> 1600
```

**为什么这一步现在特别重要**：厂商口径把驱动器拨成 **1600 脉冲/圈 + 0.5A**。
若真实是 400 步/mm 而软件按 800 发脉冲，Admin 里设 20mm/s 会按 **40mm/s** 发
（≈10 转/秒 @1600 脉冲/圈）—— 0.5A 的转矩**必然跟丢**，现象就是"只嗡嗡响、不转圈"。
这也是**出厂速度从 20mm/s 退到 2mm/s（`fac_ver=4`）**的原因：先让它能转起来。

> ★ **更正（v5，2026-09-22 晚）**：厂商那条 **0.5A 是错的** —— 现场能跑通的拨码是
> `ON OFF OFF` = **2.0A**（差 4 倍，见 9.2.1 ③ 的最终表）；而且 2mm/s 比能跑通那版
> 慢 10 倍、正好落在低速共振区。
> 所以出厂参数已回到 **`20mm/s` / `accel=decel=150mm/s²`（`fac_ver=5`）**，
> 与 Arduino 版逐项一致；上面"先退到 2mm/s"的结论**作废**。

**速度范围**由 `app_motion.h` 的两个宏夹出来（v8 起，依据见 **9.12**）：

```

> 于是 v8：
> - **运动曲线整体抬到起跳频率以上**：起步第一拍就是 8500Hz，收尾减速到 8500Hz 就结束
>   （不再进出低频禁区）；效果上等价于例程的"上电即 8500Hz 连跑"；
> - 出厂 `speed` = **10.625mm/s**（= 8500Hz，`fac_ver=8`）；`accel/decel` 仍 150mm/s²
>   （只在把 Speed 调高时才起作用）；
> - **`MOTION_TURN_FREQ_MIN_HZ = 8500`**：既是巡航下限（低于它会把 Speed 抬上来并 WARN），
>   也是整条曲线的最低频率；
> - `MOTION_STEP_FREQ_MAX_HZ` 保持 **20000**（与 Arduino/例程一致）——
>   ★ **但只有 8500Hz 被验证过**，往上调之前先用 `mtest` 逐档确认。
> **一句话：不要把 Speed 往低调 —— 在这台机器上"慢"等于"不动"。**
> 完整依据 / 复量方法 / 与 v6 那条"上限 1200Hz"的关系 ⇒ **9.12**。

> ★ **注意区分三条线**（别混）：
> - **起跳频率**（低频禁区上沿）≈ `5.3 × 脉冲每圈` —— 本机 **8500Hz**
>   （就是 `stepper_motor` 例程上电固定段验证过的档），软件把它当作
>   **巡航下限 + 整条曲线的最低频率**（起步第一拍就是它，收尾也停在它）；
> - **安全上限** `MOTION_STEP_FREQ_MAX_HZ / steps_per_unit`（现在 = 20000/800 = 25mm/s）；
> - **机械上限** = 这台机器（带载、当前电压、当前细分/电流）真实能跟上的步频 ——
>   v6 曾在**另一种细分（200 脉冲/圈）**下量到约 1200Hz，换算成转速与这次的
>   8500Hz @1600 脉冲/圈 ≈ 同一水平（5~6 转/秒）。
> - 诊断工具 `mtest`（9.11）与 `ROLLCOATER_MOTION_SELFTEST` **不受安全上限约束**
>   （诊断档 20000Hz），专门用来**复量起跳频率与上限**；
>   换电机 / 换驱动器 / 改细分 / 改供电后必须重量。

### 9.6 上电顺序与首次调试

1. **先脱开电机**（或不装联轴器），只接驱动器信号线，避免第一次就飞车。
2. 保持 `MOTION_SIMULATE=y` 烧录，按第 7 节把 HMI 全流程走一遍。
3. `menuconfig` 关掉 `无电机调试模式（MOTION_SIMULATE）` → 重新烧录。
4. **先跑一次频率扫描自检**（`ROLLCOATER_MOTION_SELFTEST`，**换机器/换拨码时**才需要，
   见 9.7 第 2 步）：记录"从哪一档开始只嗡嗡不转" → 这就是机械上限；同时量一下每档位移，
   顺便核对 `Steps per unit`。**测完请把它关掉**（默认就是关的），免得每次上电电机都动一下。
5. 示波器量 **IO11**：下发运动指令后应看到 40Hz ~ 20kHz 的方波。
6. 量 **IO13**：State1 / State3 为**高**（脱机，能盘轴）→ 进 State2 后变**低**（使能）。
   量 **IO12**（DIR）：目标增大方向应为高。
   （嫌来回量麻烦：打开 **9.8 的三线自检**，它会把这两根线每 2s 交替翻转并打印读回值，
   还给出"手扶轴判 ENA"的判据。）
7. **确认速度**：出厂 `Speed` = **15.000mm/s**（= 12000Hz，与串口 `run` 同频，
   现场验证"转得很好"）、`accel/decel` = **150mm/s²**、`fac_ver = 13`
   （v13 起；见 §6 的改动史与 9.12.7）。
   ★ **测转速请用 ≥5mm 的行程**：曲线**整段恒定 12000Hz**（无加速段、**无减速段**，
   与串口 `run` 同构，见 9.12.7.2）；行程太短会因整段只有一两拍而看不出匀速。
   ★ **不要把 Speed 调到 8500Hz 附近** —— 那是"能转"的下沿/临界点，带载会"左右转"。
   带载跑不动就按第 4 步的上限在 Admin 里**往下调**（`Speed ≤ 上限Hz / 步数每毫米`）。
   方向反了就把 `MOTION_DIR_POSITIVE_LEVEL` 从 `1` 改成 `0`，或者对调电机任一相线。
7. 确认反向补偿：反向运动时会先走掉 `backlash`（默认 0.2mm）的间隙，但**报告位置仍精确等于目标**。

### 9.7 ★「电机不转」五分钟定位表（2026-09-22 新增）

> ## ★ 现场结论（2026-09-22，已解决，别再重复排查）
>
> 硬件：**42BL233 = 4 线两相步进**（不是无刷）+ **TB6600** + 22V 供电。
> 症状：两套固件（Arduino 版 / 本工程）都是**只嗡嗡响、不转圈**。
>
> 用本节的**频率扫描自检**逐档跑 200Hz→16kHz，结果是
> **每一档都正常转圈（含 16kHz = 20mm/s）** ⇒ **"频率太高"被排除**；
> 日志侧 `请求 16000 个脉冲 / 10025 事务，RMT 报告 26025 个符号`、
> 耗时 10.43s = 16000÷1600 精确对上 ⇒ **固件侧无问题**。
>
> 真正把故障修掉的是下面两处**脉冲链路**改动（一次性一起改的，事后无法单独归因，
> 两条都是更稳妥的方向，**不要再改回去**）：
> 1. 一个 RMT 事务从"1 个符号 + `loop_count` 循环"改成**摆满 n 个脉冲符号、不循环**；
> 2. STEP/DIR/ENA 的**驱动能力拉满**（CAP_3，3.3V 直驱 5V 光耦输入时余量本来就小）。
>
> #### 示波器对照（2026-09-22 现场逻辑分析仪）
>
> | | 周期 | 高电平 | 低电平 | 对应 speed |
> |---|---|---|---|---|
> | 本工程（当时） | **125 µs**（8.000 kHz） | 10 µs | 115 µs | 10 mm/s |
> | 现场"参考"那一版 | **64.3 µs**（15.549 kHz） | 5.5 µs | 58.8 µs | 20 mm/s |
>
> ★ 两张图的**形状本来就是同一种**（窄高脉冲 + 长低电平，占空比都在 8% 上下），
> 差别只有**频率**（= speed 设置）和**脉宽**（10µs vs 5.5µs）。
> 为逐项对齐、少一个变量：脉宽改回 **5µs**、出厂 speed 改回 **20mm/s（=16kHz）**
> （= 0.33s 到满速，accel 60mm/s² 是从 150 降下来的温和值）。
> ⚠️ 注意 `Width` 这个测量项在两张图里都是**低电平时间**（自证：58.8/64.3 = 91%
> 的"高电平占比"不可能来自那套窄脉冲代码）；要看占空比请直接看 **Duty Cycle**，
> 或按上表的高/低电平去读。
>
> 收尾：`ROLLCOATER_MOTION_SELFTEST` **默认关闭**（只在换机器/换拨码时打开，
> 否则每次上电电机都会动 1.75mm）。
>
> #### ★ 2026-09-22 晚：厂商拨码口径到手后的三条结论（v4）
>
> 厂商要求 **SW1~SW3 = 1600 脉冲/圈、SW4~SW6 = 0.5A**（原文与表格见 9.2.1 ③）。
> 随之必须处理三件事：
>
> 1. **步数/mm 要跟着算**：`1600 ÷ 导程`。导程 2mm → 800（与默认自洽）；
>    导程 4mm → **400**，必须把 `ROLLCOATER_STEPS_PER_UNIT` 改成 400（见 9.5）。
>    ★ 填错的后果**不是"不转"**，而是**只走一半、且按两倍速度发脉冲** ——
>    0.5A 下那正好表现为"起步就堵转、只嗡嗡不转"。
> 2. **出厂速度退到 2mm/s / accel 30mm/s²**（`fac_ver=4`，换固件自动生效，
>    只重置 speed/accel/decel）：0.5A 的转矩很小，20mm/s（@800 步/mm = 16kHz；
>    @1600 脉冲/圈 ≈ 600 RPM）几乎不可能跟得上。确认能转后再用扫频往上调。
> 3. **拨码改完必须断电重启驱动器**（TB6600 只在复位时采样 DIP），
>    且 `NC`（SW1~3 全 ON）档**可能完全不响应脉冲** —— 别停在那一档。
>
> #### ★★ 同日晚些时候的更正（v5）：v4 的第 1、2 条都被现场推翻了
>
> 现场给出决定性事实：**同一台机器用 Arduino 版固件能正常跑通**，而它那套拨码是
> **「只有 SW2、SW4 是 ON」** ⇒ 按 9.2.1 ③ 的两张表反查：
> **细分 `OFF ON OFF` = 1600 脉冲/圈**（与厂商文档一致 ✅）、
> **电流 `ON OFF OFF` = 2.0A**（**厂商文档写的 0.5A 是错的，差 4 倍** ❌）。
> 所以：
> 1. **拨码按"能跑通的那套"**（`OFF ON OFF | ON OFF OFF`），厂商文档只作参考；
> 2. **出厂参数回退到 `20mm/s` / `accel=decel=150mm/s²`**（`APP_CFG_FACTORY_VERSION = 5`）
>    —— 直接**照抄 Arduino 能跑通那版的 `MOTOR_SPEED/ACCEL/DECEL_DEFAULT = 20/150/150`**。
>    2mm/s 比它慢 10 倍、配合 1/5 的电流正落在步进电机的**低速共振区**，
>    表现就是"空载也原地来回微抖"；accel 用 150 而非 60/30 也是为了**快速跨过共振带**
>    （0→20mm/s 只需 0.133s）。
> 3. 不重编也能立刻试：**Admin 里把 `Speed` 改成 `20.000`、`accel`/`decel` 改成 `150`**。
> 4. **测转速请用 ≥5mm 的行程**：变速距离 = 1.33mm(加) + 1.33mm(减) ≈ 2.67mm，
>    更短的行程走三角形曲线、到不了满速（这是 Arduino 规格里就写明的一条）。

现场只报了"马达不转"一句，而原因横跨**软件 / 接线 / 驱动器 / 供电**四层，
且界面、位置读数、状态机看起来全都正常（位置读数**本来就不依赖脉冲**，
模拟模式下也会动）——所以先把"代码到底有没有发脉冲"这件事变成**看得见的日志**。

**2026-09-22 改了两处**（都在 `app_motion.c`）：

1. **一个 RMT 事务里摆满 n 个脉冲符号，`loop_count` 恒为 0**（原来靠
   "1 个符号 + loop_count 循环"）。旧写法的隐患：驱动在编码结束后会紧跟一个
   `duration=0` 的结束符，而它在硬件语义里就是"停止"；循环模式到底循环"这段
   payload"还是"整块 96 个符号内存"文档没写清，一旦按后者解释，实际脉冲频率会
   被从没写过的残留符号拉长（电机只抖不转），或者循环永远收不了尾
   （`on_trans_done` 不来 → 队列填满 → **之后一个脉冲都不发**），而
   `rmt_transmit()` 全程返回 ESP_OK、日志一条报错都没有。现在符号数 = 脉冲数，
   不再依赖任何循环语义。
2. **每次运动结束打"脉冲核对"**：请求脉冲数 / 入队事务数 / 发完事务数 /
   硬件报告的符号数，四个数能对上就说明**每个脉冲都真的出了引脚**。
   另外每次下发运动时把 DIR/ENA 的**实测电平**也打出来。

按下面顺序看一眼就能定位该修哪一层：

**第 0 步：确认烧的是真机固件（最常见的乌龙）**
- 看开机日志 `Motion  : STEP=11 DIR=12 ENA=13 ALARM=-1 (REAL)`
- 若显示 `(SIMULATE)` → 这版固件**根本不驱动 STEP/DIR/ENA**，位置读数照样会动，
  界面看起来一切正常、只有电机不转。重新 build + flash，并确认
  `menuconfig -> Roll Coater HMI 配置 -> 无电机调试模式` 是**关闭**的。
- 本目录里曾有早期用 SIMULATE 编的 `build_verify/`，已在 2026-09-22 删除，
  就是怕误烧那个 bin；请只用 `build/`。

**第 1 步：让代码自己交代"脉冲发出去了没有"**（下发任意一次运动）

```
Move: 0.000 -> 30.000 mm (24000 steps, backlash 0, 16000 steps/s = 20.0 mm/s)
  STEP=IO11 DIR=IO12(1) ENA=IO13(0, 0=使能) 脉冲上限 64 步/事务
脉冲核对 OK：请求 24000 个脉冲 / 1500 个事务，RMT 报告 25500 个符号
```
（符号数 = 请求脉冲 + 事务数：每个事务多 1 个由驱动自动补的结束符）

| 你看到的 | 结论 | 下一步 |
|---|---|---|
| 没有 `Move:` 这一行 | 根本没下发运动（输入/状态机没走到 State2） | 看同一时刻的 `Submit ... in State N` |
| `rmt_transmit failed: ...` 或 `★★ 位置在推进，但 rmt_transmit() 全部失败` | 脉冲没交给 RMT 硬件：**软件问题** | 把报错原文贴出来；多半是 RMT 资源被别的模块占了 |
| `★★ 脉冲核对异常：… 入队 K / 发完 J …` | 有事务卡在 RMT 里没发完 | 同上，贴报错原文 |
| `脉冲核对 OK：…` 但电机不转、也不响 | 脉冲**已经出引脚** → 代码无罪 | 走第 2 步 |
| 日志里 `ENA=IO13(1, ...)` | 使能没拉低（只该在 State1/State3 出现） | 查状态机是否真的进了 State2 |

#### 现场实测记录（2026-09-22，42BL233 + TB6600 + 22V；当时还是调试期的 speed=2mm/s）

```
I app_motion: Move: 0.000 -> 20.000 mm (16000 steps, backlash 0, 1600 steps/s = 2.0 mm/s)
I app_motion:   STEP=IO11 DIR=IO12(0) ENA=IO13(0, 0=使能) 脉冲上限 64 步/事务
I app_motion: 脉冲核对 OK：请求 16000 个脉冲 / 10025 个事务，RMT 报告 26025 个符号
I app_motion: Arrived at 20.000 mm (16000 steps)        ← 228.2s → 238.6s = 10.4s ≈ 16000/1600
```
**结论：软件 / RMT 层 100% 正确** —— 20mm×800 = 16000 个脉冲全部交给硬件、且硬件报告
发完（16000 + 10025 个结束符 = 26025 个符号），耗时也正好等于 16000÷1600。
所以"电机不转"的原因**一定在 IO11 之后的链路**：TB6600 / 电机 / 电流拨码 / 3.3V 电平 / 接线。

⚠️ 这次日志里有两行**看着像故障、其实不是**（都已在 2026-09-22 修掉，重编后不再出现）：

| 日志 | 真相 | 处理 |
|---|---|---|
| `E rmt: rmt_tx_wait_all_done(592): flush timeout`（低频档刷十几条红字） | 旧版"等发完"用了 `rmt_tx_wait_all_done(chan, 20)` 轮询，而自检 200Hz 档一个事务长达 320ms，必然超时 → **驱动自己打的红字**。注意它下面紧跟的就是 `脉冲核对 OK：…发完 4` | 改成等 `s_tx_pending` 归零 + 非阻塞回收，不再刷屏 |
| `DIR=IO12 实测=0`（目标增大时 DIR 本该=1） | **读回假象**：旧代码用 `GPIO_MODE_OUTPUT`，而 `gpio_config()` 会把该脚的**输入通路关掉**（`gpio.c:369-374`），于是 `gpio_get_level()` 恒返回 0 | 改成 `GPIO_MODE_INPUT_OUTPUT`；从此 DIR/ENA 的读回是**真实电平**，"设 1 读回 0" 会直接打 `★★ DIR(IO12) … 被外部拉住` 的 ERROR |

**第 2 步：跑"频率扫描自检"，直接把"频率上限"测出来**

> ★ 这一条是针对现场真实反馈加的：**电机只嗡嗡响、不转圈**，而且
> 同现场 Arduino 版在 22V 下也是同样现象 —— 说明问题**不在本工程的 RMT 代码**，
> 而在"这台机器（带载 / 当前电压 / 当前细分与电流）能跟上的步频"。
> 所以自检从"单频点正反转"改成**逐档升频**，让机器自己说出上限在哪一档。

**默认是关闭的**（2026-09-22 现场已测完，留着它每次上电电机都会动一下）。
要复查/换机器时打开：`menuconfig -> Roll Coater HMI 配置 -> 上电做一次 STEP/DIR/ENA
裸脉冲自检` 选 **Y**，或把 `sdkconfig`（和 `sdkconfig.defaults`）里那行改成
`CONFIG_ROLLCOATER_MOTION_SELFTEST=y`，重编烧录。
打开后上电时（屏幕还是白屏）电机会依次走：
**200Hz → 500Hz → 1k → 2k → 4k → 8k → 16kHz，每档 200 步、档间停 0.4s**，
最后按 500Hz 原路退回（行程 1400 步 = 1.75mm @800 步/mm，约 5~6 秒走完）。

```
=== 频率扫描自检开始：7 档 × 200 步（每档 0.25 mm，共正转 1.75 mm 后原路退回）★ 电机会动 ===
判断①（频率）：从哪一档开始「只嗡嗡响、不转圈」，上一档就是上限；……
判断②（机械参数）：每档固定 200 步，若 steps/unit 正确(800)，每档应移动 0.25 mm。
   ★ 实测位移明显偏大/偏小 = 驱动器细分 DIP 与 Steps per unit 不一致：
     真实 steps/unit = 200 / 实测每档位移(mm)。
档 1/7：200 Hz（= 0.250 mm/s）x 200 步（DIR=IO12 实测=1；ENA=IO13 实测=0，0=使能）
   脉冲核对 OK：请求 200 / 入队 4 / 发完 4，RMT 报告 204 个符号
…（0.4s）…
档 4/7：2000 Hz（= 2.500 mm/s）x 200 步
   脉冲核对 OK：请求 200 / 入队 4 / 发完 4，RMT 报告 204 个符号
…（0.4s）…
档 5/7：4000 Hz（= 5.000 mm/s）x 200 步
   ← 假设从这一档开始只嗡嗡响不转，那上限就是 2000Hz
=== 反转退回 1400 步 @500Hz ===
```

| 自检现象 | 结论 | 下一步 |
|---|---|---|
| 每一档都平稳转圈 | 三根线、供电、驱动器全没问题 | 只剩 Speed / accel / 负载（9.2、9.4、9.5） |
| **从第 k 档开始只嗡嗡响、不转圈** | **机械上限 = 第 k−1 档的 Hz**（现场最可能的情况） | Admin 里把 `Speed` 设成 ≤ (第 k−1 档 Hz)/800 |
| 第 1 档（200Hz）就只震不转 | **与频率无关**：相序 / 细分 / 电流 / 只接一相 | 见下面「只震动不转圈」清单 |
| 每档实测位移都明显偏大/偏小 | 驱动器细分 DIP 与 `Steps per unit` 不一致 | 用 `200 / 实测位移` 反推真实 steps/unit，两边同步改 |
| 只有反转那段动 / 只有正转动 | DIR 接线或极性 | 量 IO12 在两段之间有没有翻转 |
| 都不动、也没有任何声音 | ENA 或 STEP 断线 / 驱动器没上电 / **信号地没共地** | 9.1、9.4 |
| 日志里 `入队 0` | 脉冲没交给 RMT：软件问题，不是接线 | 贴日志 |

> 测完**记得关掉自检**（否则每次上电电机都会动一下）：本工程**默认就是关的**；
> 如果你为了排障手动打开过，把 menuconfig 里那一项选回 **N**
> （或把 `sdkconfig` / `sdkconfig.defaults` 里那行改回
> `# CONFIG_ROLLCOATER_MOTION_SELFTEST is not set`），重新编译烧录即可。

**第 3 步：只震动不转圈（嗡嗡响）的排查顺序**

按代价从小到大，一条一条试（现场 22V、10 档里踩过前三条）。
★ 现场用的是 **TB6600 + 42BL233（4 线两相步进）**：请**先做 9.2.1 的"手动点脉冲"实验**，
它 1 分钟就能把固件 / 频率 / 代码全部排除，直接分出"是硬件还是软件"。
（★ 本机这组硬件的同类问题已于 2026-09-22 解决，见本节开头的"现场结论"。）

1. **先降速度**：Admin 里把 `Speed` 从 20.000 往下调（10.000 → 5.000 → 2.000）。
   若低速能转、高速只嗡嗡，那就是机械上限；若**低速也完全不动**，
   **基本可排除"频率太高"**，直接跳到第 3~5 条。
   （★ 本机现场实测：200Hz~16kHz **每一档都正常转圈**，即频率不是瓶颈，见本节开头结论。）
2. **再降加速度**：`accel` 从 60mm/s² 降到 30 / 20。加速太猛会在起步瞬间就堵转，
   现象与"频率太高"完全一样；也可以顺便把 `decel` 一起降。
3. **降细分并同步改 Steps/unit**：驱动器 DIP 从 16 细分降到 8 或 4
   （更高细分 = 每步转矩更小、更容易堵转），同时把 Admin 的
   `Steps per unit` 按同样比例改（16→8：800→400），否则位置全错。
   ⚠️ **这两个必须同步改**，只改一个必然对不上。
   ★ 用第 2 步扫描里的"每档实测位移"就能反推真实 steps/unit。
4. **查驱动器电流**：DIP 电流设太小（或峰值/均值档选错）→ 转矩不够 → 堵转嗡嗡响。
   按电机铭牌设到额定的 70%~100%。
5. **查相序与接线**：`A+ A− B+ B−` 是否有接反/只接一相/一相断线。
   **判据：断电后用手转轴，两相都接好时手上有明显的"齿槽感"；**
   **只接一相时会感觉像自由转动、或只在两个位置"吸住"。**
6. **升电压/加电容**：22V 对 1.8° 小步进偏高，但转矩不足时更常见的是
   **电源功率不够**（堵转电流一大电压就塌）。电源端并 ≥470µF，线径加粗。
7. **脉宽**：本工程当前是 `MOTION_STEP_PULSE_US = 5µs`（与现场参考波形一致；
   TB6600 手册的 PUL 最小脉宽是 2.5µs）。**若出现"能转但没力/丢步"**（慢光耦吃窄脉冲），
   把它调到 8~10µs 再试；根治是换 6N137 或做电平转换（9.2）。

**第 4 步（可选）：示波器/万用表确认电平**
- IO11：下发运动时应有 40Hz ~ 20kHz 的方波，**5µs 高 / 其余低（占空比约 8%）**；
  20mm/s 时 = 周期 62.5µs / 高 5µs / 低 57.5µs
- IO12：目标增大方向为高，反向为低
- IO13：State1/State3 高（脱机，能手动盘轴）→ State2 低（使能）
- ⚠️ 3.3V 直驱 5V 光耦输入的驱动器可能电流不足（见 9.2）：串阻 1kΩ → 470Ω/330Ω，
  或加 74HCT245。本工程已把 STEP/DIR/ENA 的**引脚驱动能力拉到最大**（≈40mA），
  但电平仍是 3.3V，光耦余量不足时还得靠上面的电阻/电平转换。
  **判据：示波器上 IO11 波形正常、驱动器输入端 PUL 却塌掉。**

### 9.8 ★ DIR(IO12) / ENA(IO13) 两根线怎么单独验（2026-09-22 晚新增）

> 背景：STEP(IO11) 的波形已用逻辑分析仪确认到"与参考版逐项一致"
> （周期/脉宽/占空比对得上，见 9.7 的示波器对照表），怀疑就落到**另外两根线上**。
> 但此前能证明的只有"脉冲出没出引脚"（脉冲核对日志），DIR/ENA 一直靠猜。

#### 9.8.1 先看代码做了什么（与 Arduino 版逐项对齐）

| | Arduino `motor.cpp` | 本工程 `app_motion.c` |
|---|---|---|
| DIR 正方向 | `dir>0 ? HIGH : LOW` | `MOTION_DIR_POSITIVE_LEVEL = 1` |
| DIR 换向后等待 | `delayMicroseconds(2)` | `MOTION_DIR_SETUP_US = 10µs` |
| ENA 使能 / 脱机 | `digitalWrite(EN, en?LOW:HIGH)`（低有效） | `MOTION_ENA_ACTIVE_LEVEL = 0` |
| 空闲（State1 / State3） | 高 = 脱机 | 高 = 脱机 |
| **DIR/ENA 稳定到发第一个脉冲** | ~1 个 tick（ms 级） | **`MOTION_ENA_SETTLE_MS`**：v10 起默认 **100ms**（Kconfig 可配，见 9.12.5 ③） |

★ 最后一行是本次改动：原来只等 `MOTION_DIR_SETUP_US`(10µs) 就开脉冲，而
**唯一被现场证明"电机会转"的路径**——频率扫描自检——的顺序是
「设 DIR → ENA 拉低 → `vTaskDelay(20ms)` → 才发脉冲」。
TB6600 这类**光耦隔离输入**的驱动器，ENA 由高变低后光耦导通 + 输出级使能 + DIR 建立
都要 ms 级时间，10µs 之内发出去的脉冲驱动器根本不计。现在两条路径在 DIR/ENA 上完全一致。
（"能转的那条路径"就是把 `ROLLCOATER_MOTION_SELFTEST` 打开时跑的那段代码。）

#### 9.8.2 三线自检：只动 DIR/ENA，一个脉冲都不发

```
menuconfig -> Roll Coater HMI 配置 -> 上电做一次 DIR/ENA「三线自检」= Y
（或 sdkconfig 里 CONFIG_ROLLCOATER_MOTION_WIRE_TEST=y）
```

上电时（**轴不会走** —— 一个脉冲都不发，可放心反复跑）依次打印：

```
=== 三线自检开始（不发脉冲，轴不会走）===
判读：① 万用表量 IO12(DIR) / IO13(ENA) 对 GND，应 3.3V 与 0V 交替；② 手扶轴：…
ENA 使能：IO13 设 0 读回 0（OK）——【现在轴应有保持力矩：盘起来明显变硬】   ← 每段停 2s
ENA 脱机：IO13 设 1 读回 1（OK）——【现在轴应能自由盘动：没有保持力矩】
（再来一轮）
DIR 正方向：IO12 设 1 读回 1（OK）
DIR 反方向：IO12 设 0 读回 0（OK）      （再来一轮）
=== 三线自检结束（已回到上电姿态：DIR=1、ENA=脱机；测完请关掉 WIRE_TEST）===
```

| 现象 | 结论 | 处理 |
|---|---|---|
| 日志里 `读回不符`（★★ ERROR） | 引脚被外部拉住：短路到 GND / 端子接错 / 驱动器输入异常 | 拔掉那根线再跑一次；拔了就正常 = 线缆或驱动器侧 |
| **打印【使能】时轴一直很松**（没有保持力矩） | **驱动器没收到使能信号** ← 判 ENA 的决定性判据 | ① ENA 是否接在驱动器的 ENA/EN 端子；② 有的驱动器 ENA 是**高有效**、或端子语义是【脱机/关输出】→ 把 `app_motion.h` 的 `MOTION_ENA_ACTIVE_LEVEL` 改成 1 重烧；③ 干脆拔掉 ENA 线试（多数驱动器不接 ENA = 一直使能） |
| 打印【使能】变硬、【脱机】变松 | ENA 这一路完全正常 | 回去查 STEP / DIR（9.7 第 1~3 步） |
| 万用表量 IO12 两段之间不翻转 | DIR 没到驱动器 | 查 DIR 端子/线缆；方向仍反就对调任一相线或把 `MOTION_DIR_POSITIVE_LEVEL` 取反 |
| **转的时候方向老是乱跳**（v14） | ① 改 DIR 时 RMT 队列里还有上一段的残余脉冲（`app_motion_stop()` 不清队列，最多 3 事务 ≈12ms）⇒ 旧脉冲带着新 DIR 电平出来；② `mtest run` 与界面在途运动同时抢 RMT/DIR | ① v14 已在 `motion_begin()` 里改 DIR 前先 `motion_wait_tx_done()`；② v14 已在 `motion_task()` 里 `run` 启动时 `motion_abort()` 停掉在途运动。若日志里 `Direction reversed, apply backlash 160 steps` **频繁**出现 ⇒ 是上游在连续下发相反方向的目标（查操作节奏/UI） |

#### 9.8.3 每次下发运动都会打印 DIR/ENA 的**稳态**电平 + 读回校验

```
Move: 0.000 -> 30.000 mm (24000 steps, backlash 0, 16000 steps/s = 20.0 mm/s)
  STEP=IO11 DIR=IO12(1) ENA=IO13(0, 0=使能) 脉冲上限 64 步/事务
```

这两行现在是**等完 20ms 稳定时间**才打的（= 驱动器将要看到的电平），
而且 DIR / ENA 都会与期望值比较，不符直接打 `★★` ERROR：

- `★★ DIR(IO12) 设成 1 但读回 0：该引脚被外部拉住（短路到 GND / 接错端子 / 驱动器 DIR 输入异常）`
- `★★ ENA(IO13) 设成 0(=使能) 但读回 1：驱动器没收到使能信号 —— …`

> ⚠️ 只有出现 `DIR=IO12(0)` 而本次是**目标增大**、或 `ENA=IO13(1)`，
> 才说明这两根线真有问题；否则"代码已经把这两根线拉对了"，
> 请回到 9.7 第 2 步（频率扫描自检）与 9.2.1（TB6600 专查）。

### 9.9 ★「脉冲核对 OK，电机还是抖动/不转」怎么收口（2026-09-22 晚，现场正在进行）

现场日志已经把**固件侧全部排除**：

```
Motion ready (REAL): 800 steps/unit, speed 2.000 mm/s (= 1600 steps/s) …   ← v4 生效
Move: 0.000 -> 20.000 mm (16000 steps, backlash 0, 1600 steps/s = 2.0 mm/s)
  STEP=IO11 DIR=IO12(1) ENA=IO13(0, 0=使能) 脉冲上限 64 步/事务          ← 两根线都对，无 ★★
脉冲核对 OK：请求 16000 个脉冲 / 10025 个事务，RMT 报告 26025 个符号       ← 脉冲全出引脚
Arrived at 20.000 mm            （10806ms → 21220ms = 10.4s ≈ 16000÷1600） ← 速率也对
```

⇒ 脉冲数、速率、DIR/ENA 电平**全部正确**，按 9.7 第 1 步的判据表，
这种情况**只剩硬件**（含"驱动器输入端那一段光耦"）。

按信息量从大到小做，**前三步都零成本、一分钟出结论**：

**① 手动点脉冲 —— 一次把"驱动器+电机+接线"与"信号这一路"劈成两半**
（做法见 9.2.1 ①：`PUL- / DIR- / ENA-` 接 GND，用 +5V 手动以 1~2 次/秒点 `PUL+`）

> ⚠️ **做这个实验前请把细分切到「整步 200 脉冲/圈」**（按驱动器外壳的表选 `Pulse/rev = 200`
> 那一行，SW4 保持 ON = 2.0A），否则 1600 脉冲/圈 时**一个脉冲只有 0.225°，肉眼根本看不见**，
> 你会误判成"点了没反应"。整步时一个脉冲 = 1.8°，点 20 下就是 36° —— 一眼就能看出来。
> 同理，`mtest` 想用慢速看"一步一步走"，也在整步档下试：
> `mtest 40 5 200`（40Hz、占空比 50%、200 步）= 整整一圈，走 5 秒。

- 跟着点**能一步一步转** → 驱动器/电机/相序/电流都没问题 → 问题在信号侧：
  3.3V 直驱 5V 光耦（电流只有约 2mA）不够 → 改**共阳**（`+` 接驱动器 5V、`−` 接 ESP32），
  或串阻降到 470Ω/330Ω，或加 74HCT245。
- 还是**只抖不转** → 与固件、波形、频率**统统无关**，看 ②③④。

**② 脱开联轴器（空载）再走一次界面运动**

- 空载能正常转 → **转矩/电流**问题：厂商口径的 0.5A 对带丝杠的 42 电机偏小，
  按 9.2.1 ③ 的表往上试 **1.0A（`ON ON OFF`）**，再不行 1.5A（`ON OFF ON`），注意发烫。
- 空载也只抖 → 相序 / 接线 / 驱动器 / 电机类型（看 ③④）。

**③ 电机相线分组（"接错分线"的典型现象就是原地抖）**

断电拔线，万用表两两量：

| 量到的 | 结论 |
|---|---|
| 恰好两组：组内几 Ω、**组间不通** | 正常两相步进 ✅ |
| 任意两根都通 | 不是两相步进（三相无刷？）→ **TB6600 驱动不了，得换驱动器/电机**（9.2.1 ④） |
| 只有一组通 | 有一相开路（线圈断/线断）→ 只会抖 |

接线必须**一组进 A+/A−、另一组进 B+/B−**。★ 最常见的错接是 `(A+,B+)/(A−,B−)` 交叉分线。

**④ 拨码必须是 `OFF ON OFF | ON ON ON`，且改完**断过驱动器电源**重新上电**

`SW1~3` 全 ON 的 `NC` 档是"未定义档"，**本身就表现为只抖不转**。

**⑤ 量驱动器端子，而不是 ESP32 引脚**

ESP32 侧波形漂亮 ≠ 光耦那边认。量 `PUL+↔PUL−`、`DIR+↔DIR−`、`ENA+↔ENA−` 有没有对应跳变。
**ESP32 侧有、驱动器端子没有 = 接线 / 共阳共阴接错 / 光耦不导通。**

**⑥ 软件侧唯一还没排除的变量：脉宽（1 分钟能试完）**

```
menuconfig -> Roll Coater HMI 配置 -> STEP 高电平脉宽 (µs，0 = 50% 方波)
```
默认 `5`（与参考波形一致）→ **先改 `50`，再改 `0`**，各烧一次看现象是否变化。
理由：TB6600 是光耦隔离输入，3.3V 直驱时 LED 电流约 2mA、上升沿慢，
5µs 的窄脉冲可能被判成"时有时无" → 丢步 / 原地抖动。
（低电平永远留一半周期，调多大都不会把低电平挤没；默认 5µs 的输出与旧固件逐位相同。）

**★ 贴胶带实验（一次同时判定"拨码细分"和"Steps per unit"）**

在联轴器/丝杠上贴一条胶带做标记，下发一次 **20mm** 运动（固件会发 **16000** 个脉冲），
**数圈数 + 量实际位移**：

| 转了几圈 | 说明（16000 ÷ 圈数 = 驱动器实际脉冲/圈） |
|---|---|
| **10 圈** | 驱动器确实是 **1600 脉冲/圈** ✅（厂商拨码正确） |
| 5 圈 | 驱动器是 3200 脉冲/圈（16 细分档） |
| 20 圈 | 驱动器是 800 脉冲/圈（4 细分档） |
| 2.5 圈 | 驱动器是 6400 脉冲/圈（32 细分档） |

再比"**实际位移 = 圈数 × 导程**"与界面读数（20.000）：

| 对比 | 结论 |
|---|---|
| 实测 = 20.000 | `Steps per unit` 正确 ✅ |
| 界面读数是实测的 **2 倍** | 本值填大了 → 改成一半（800 → 400） |
| 界面读数是实测的 **一半** | 本值填小了 → 改成两倍 |

★ 原地不动 / 只抖 → 直接走上面 ①②③④，不用纠缠 9.5 的数值。

### 9.11 ★ 串口命令行 `mtest`：手动"换挡试转"（2026-09-22 晚新增）

> 背景：日志已经证明「脉冲数 / 速率 / DIR / ENA 电平全对」（见 9.9），现场仍是
> "**转一点 + 抖**"。这时能在软件里扫的变量只剩两个 —— **脉宽**（3.3V 直驱光耦、
> 5µs 窄脉冲可能被丢）与 **频率**（= speed × 步数/mm；这台机器**低频不走、高频拖不动**，
> 只有中间一段能用，见 9.12）。与其反复改代码烧录，不如直接在串口里换挡试。

打开方式：`menuconfig -> Roll Coater HMI 配置 -> 串口命令行（mtest / f / run / stop）`，
**★ 默认关闭（v12 交付配置）**：它是一条"直接发脉冲、不经界面状态机"的调试通路，
交付件里不该存在。排障/换机器时临时打开（`CONFIG_ROLLCOATER_MOTION_CONSOLE=y`）。
烧完后在串口监视器里直接敲（**UART0 / 115200**，必须用板载 COM 口，不能用原生 USB，见 9.1）：

```
mtest                 用当前设置跑一次（默认 **12000Hz** / 每方向 **1600 步 = 2mm**，净位移 0）
mtest 12000           设频率 12000Hz（= 15mm/s @800 步/mm）再跑 ← 当前默认值
mtest 8500            设频率 8500Hz 再跑 ← 台架验证**连续平稳**的那档（保底）
mtest 12000 50        再设脉宽 50µs（5 = 默认 / 0 = 自动 50% 方波）
mtest 12000 5 3200    第三个参数 = 每方向步数（默认 **1600 步 = 2mm**；高频档要加大）
mtest 12000 5 3200 6000  第四个参数 = 本段**加速率 Hz/s**（隔离【加速太陡】这个变量）
mtest sweep           自动跑 6 频率 × 4 脉宽 = 24 段（6000~16000Hz，骑在起跳频率两侧）
mtest hold [hz] [ms]  ★ **固定频率连发 N 毫秒**（默认 12000Hz × 10000ms）—— 与
                      stepper_motor 例程的上电段逐项同构；跑完自动停 + 脱机。真走轴！
f [hz]                ★★ **单向连续**：设频率（不给参=打印当前），**运行中也能改**（下一批生效）
run [hz]              ★★ **单向连续**：开始发脉冲，**一直转到 stop**（不是来回了！）
stop                  ★★ 停止连续运行（等脉冲发完 + 脱机）；没在跑时也把界面运动停掉
mtest bb [频率] [脉宽] [步数]   ★ 对照实验：**软件翻转 IO11** 发脉冲（绕开 RMT，照 Arduino 的做法）
mtest def             脉宽恢复出厂默认
help                  列出所有命令
```

> ★ **默认频率 `12000Hz`、默认步数 `1600`**（v13 起 = 界面工作点，两者同频）。
> ★ **现场复测（v13）：`f 12000` + `run` 单向连续"转得很好"** —— 这就是工作点。

#### 9.11.1 ★★ `f` / `run` / `stop`：与 stepper_motor 台架**同参数**的单向连续（v16 新增）

现场用台架那三条命令（`f 12000` → `run` → `stop`）判"这一段能不能连续转"最省事，
所以把**同样语义**的三条命令搬到本工程（`app_motion.c` 的 CLI 段）：

| 命令 | 行为 | 与台架的对应 |
|---|---|---|
| `f [hz]` | 设连续运行的频率（不给参数 = 打印当前）；**运行中改也生效**（下一批脉冲） | 完全一样 |
| `run [hz]` | **单向连续**发脉冲（DIR 固定不换向、不经曲线/状态机），一直转到 `stop` | 完全一样（台架 `run` 不带参数也是 RUN_CONT） |
| `stop` | 停止连续运行：等最后几个事务发完 → 脱机 → 打脉冲核对；没在跑时等价于界面 STOP | 一样 |

★ **为什么必须单独做一条 `run`**（而不是用 `mtest hold`）：
`hold` 是在**命令行任务里**跑完整段才回到提示符，所以**跑起来之后敲不了 `stop`**；
`run` 把发射放到**独立任务**（优先级 = `motion_task`），命令行立刻回到提示符 ⇒
`stop` 随时可用、`f` 能运行中换挡。

★ 方向**固定正向**（`MOTION_DIR_POSITIVE_LEVEL`，全程不换向）⇒ 看到/听到"来回摆"
就一定是**电机在这个频率上失步**，不可能是软件在换向（这也是它比 `mtest` 更干净的地方：
`mtest`/`sweep` 是"正转 N 步再反转 N 步"，本来就是来回的）。

★ 连续运行期间：**界面下发的运动会被忽略**（日志 `★ mtest run 连续运行中：忽略本次界面运动`），
其它 `mtest` 子命令也会被拒绝（先 `stop`）—— 避免两处同时往 RMT 灌脉冲。

★ 现场用法（就三条）：
```
f 12000        ← 或直接 run 12000
run
   ...看/听：连续平稳？发毛？来回摆？...
stop
```
日志会打 `=== 连续运行开始：… ===` 和 `=== 连续运行结束：…（平均 xxx Hz，目标 xxx Hz）；轴已脱机`，
外加一条**脉冲核对**（`RMT 符号数 = 请求脉冲 + 事务数`）——平均频率明显低于目标 = 补队列被拖过。

### 9.12 ★★ 照抄 `stepper_motor` 例程：8500Hz 曲线（v8）+ 50% 波形与上电固定段（v9）

> 现场决定性事实（用户原话）：同工作区的
> **`examples/peripherals/rmt/stepper_motor` 上电后的头 10 秒是可以正常运行的** ——
> 那 10 秒做的事就是「使能 → **直接把频率推到 8500Hz** → 连跑 10 秒 → 停 + 脱机」。
> 也就是说：**硬件、驱动器、拨码、接线、电机全都没问题，8500Hz 这一档就是能连续转**。
>
> 而主工程（`Mult_RollCoaterHMI`）在**同一台机器、同一套接线、同一拨码**下"一步都不动"。
> ⇒ 差别只在**软件把频率摆在哪**：例程整段恒在 8500Hz，主工程原来是
> `0 → 800Hz` 的爬升 + 收尾降回 0，**整条曲线大部分时间待在低频禁区里**。

#### 9.12.1 对照（同一台机器，两台固件，同一拨码）

| | `stepper_motor` 上电固定段（能转 ✅） | `Mult_RollCoaterHMI`（v6/v7 之前，不转 ❌） |
|---|---|---|
| 频率轨迹 | **恒 8500Hz**，没有低速段 | 梯形：起步 50Hz → 升到 `speed×800` → 收尾降回 0 |
| 低速段占比 | **0** | 起步 + 收尾两段都在 `≈8500Hz 以下` |
| 结果 | 连续平稳转 | 只嗡嗡、轴不动（位置读数却照走） |

⇒ 结论一句话：**这台机器 ≈8500Hz 以下带不动，所以软件的整条运动曲线都必须待在它之上。**

#### 9.12.2 归一化：与 v6 那条"上限 1200Hz"并不矛盾

两次实测拨码不同，Hz 数完全不同，但换算成**转速**是同一个门槛：

| 实测 | 拨码（细分） | 脉冲/圈 | 分界频率 | 换算转速 |
|---|---|---|---|---|
| v6（2026-09-22 晚） | `ON ON OFF` | 200 | **1200Hz 以上开始抖** | 1200 ÷ 200 = **6.0 转/秒** |
| v8（2026-09-22 深夜） | `OFF ON OFF` | 1600 | **8500Hz 以下一步不走** | 8500 ÷ 1600 = **5.3 转/秒** |

⇒ 这台机器（42BL233 + TB6600 + 24V + 该负载）**只在 ≳5~6 转/秒（≈320~360 RPM）
时才带得动**，以下全是"低频禁区"。

> ★ **换算口径（改拨码后照这个算，不必重扫）**：
> ```
> 起跳频率 ≈ 5.3 × 驱动器脉冲每圈
>     1600 脉冲/圈 -> 约 8500Hz      200 脉冲/圈 -> 约 1060Hz
> ```
> ⚠️ 这个数**不是驱动器输入上限**（TB6600 的 PUL 输入能到几十 kHz），
> 而是**电机的转矩-转速特性 + 低速共振**：电流、供电电压、负载、机械别劲一起决定。
> 所以"改波形 / 改脉宽 / 改代码"都不可能把它去掉，只能**绕开**。

#### 9.12.3 v8 改了什么（★ 核心：曲线的**最低频率**）

| 项 | 改前（v6/v7） | **v8** | 依据 |
|---|---|---|---|
| **运动曲线的最低频率**（app_motion.c 的 `motion_run_profile`） | **0Hz**（起步 50Hz，收尾减到 0） | ★ **`MOTION_TURN_FREQ_MIN_HZ` = 8500Hz**：起步第一拍就是 8500Hz，收尾减速到 8500Hz 就结束 | 与例程"上电即 8500Hz"同构；低于它的脉冲电机不走，发出去只会**白记账**（位置短一截） |
| `MOTION_TURN_FREQ_MIN_HZ`（app_motion.h） | 9000 | **8500** | 直接取例程验证过的那一档 |
| 出厂 `speed`（app_config.c） | 20 mm/s（=16000Hz，**未验证**） | 10.625mm/s=8500Hz（v8/v10/v12）↔ 15.000mm/s=12000Hz（v9/v11）→ **15.000 mm/s = 12000Hz（v13，当前）** | ★ v13 更正：**12000Hz 才是工作点**（`run` 现场验证"转得很好"）；8500Hz 是下沿/临界，带载会"启动后左右转" |
| **软启动起步频率**（`ROLLCOATER_SOFT_START_HZ`） | v11~v13 默认 500Hz（会"卡壳/左右抖动"） | **0 = 关闭（v9 起默认）** | 低频段带不动，爬升等于故意在禁区里走一趟；`mtest ss <hz>` 可现场试 |
| 出厂 `accel`/`decel` | 150 mm/s² | 150 mm/s²（保留） | 只在操作员把 Speed 调高时才起作用（8500→更高那一段） |
| `MOTION_STEP_FREQ_MAX_HZ` | 20000（v7 起） | 20000（不动） | 与 Arduino 版 / 例程 `FREQ_MAX_HZ` 一致。★ 只有 8500Hz 被验证过 |
| `MOTION_SCAN_FREQ_MAX_HZ` | 20000（v7 起） | 20000（不动） | 诊断要能越过 8500 往上找上限 |
| `APP_CFG_FACTORY_VERSION` | 6 → 7 | **8** | 换固件后自动迁移（只重置 speed/accel/decel），不必 erase-flash / 进 Admin |
| **STEP 脉宽默认**（`ROLLCOATER_STEP_PULSE_US`） | 5µs（窄脉冲） | **0 = 50% 方波（v9）** | 例程（能转的那版）用的就是 50% 方波，这是频率对齐后唯一还没对齐的软件变量 |
| **上电固定段**（`ROLLCOATER_BOOT_HOLD`） | 无 | 8500Hz × 10s（v9 起有，**v12 起默认关**） | 与例程上电段逐项同构；绕开曲线/状态机/UI，直接回答"硬件认不认脉冲"（见 9.12.5） |
| **正常运动的事务批大小**（`MOTION_TX_BATCH_MS`） | 1ms/事务（8500Hz 时一个事务只有 8~9 个脉冲） | **4ms/事务（v12）** | RMT 队列余量 3ms → **12ms**（抗抢占 ×4）；事务数也少 4 倍。与固定段同一机理 |

核心代码（`app_motion.c`，**这两处就是"能不能转"的开关**）：

```c
const float v_floor = MOTION_TURN_FREQ_MIN_HZ;                  /* 8500Hz */
float v_allowed = sqrtf(2.0f * a_dec * abs_rem + v_floor * v_floor);  /* 刹到 v_floor，不是刹到 0 */
float v_req = (v_max < v_allowed) ? v_max : v_allowed;
...
if (s_vel_steps < v_floor) {        /* ★ 第一拍就抬到 8500Hz（例程的做法） */
    s_vel_steps = v_floor;
}
```

**关键换算（= 为什么以前"点点不动"）**：

```
v6 的 1.000mm/s × 800 =  800Hz   ← 禁区  ⇒ 不是"慢"，是"不动"
v10 的 10.625mm/s × 800 = 8500Hz ← 下沿/临界（空载能过、带载"启动后左右转"）
v13 的 15.000mm/s × 800 = 12000Hz ← 出厂工作点（`run` 现场验证"转得很好"）
```

> ★ **v6 留档**：那次的"上限约 1200Hz"是在 **200 脉冲/圈**（`ON ON OFF`）那套拨码下量的，
> 换成 1600 脉冲/圈后**不能直接套用**（同一转速对应的 Hz 数差 8 倍）。
> 当时把上限收到 1000、出厂速度退到 1mm/s，正是"换回 1600 脉冲/圈后一步都不动"的直接原因。

#### 9.12.4 怎么复量（串口，1 分钟）

见 9.11（`mtest` 不受软件安全上限约束）：

```
mtest 4000 5 3200      ← 落在禁区里：预期【只嗡嗡、轴不动】
mtest 8500 5 3200      ← ★ 例程验证过的档：预期【连续平稳转】
mtest 10000 5 3200     ← 往上一档试：能转就说明上限更高
mtest sweep            ← 一次跑 6000/7500/8500/10000/12000/16000Hz × 4 脉宽
```

判读只看两点（不需要仪器）：
1. **从哪一档开始"轴真的连续转"** ⇒ 那就是**起跳频率**；
2. **从哪一档开始"发毛/丢步"** ⇒ 那才是**速度上限**。

★ 诊断串**故意保留低频段**（起步 50Hz → 目标频率），因为它的任务就是找出禁区边界；
**真实运动曲线是整体抬到 8500Hz 以上的**（9.12.3），两者不要混。

#### 9.12.5 ★ v9：上电固定段（照抄例程的上电 10 秒）+ 脉宽改成 50% 方波

现场反馈"按 v8 改了还是不动"，于是 v9 做了两件事，**把最后两个没对齐的变量一起对齐**：

**① 上电固定段（`ROLLCOATER_BOOT_HOLD`）—— v12 起改为「调试开关，默认关」**

上电后、UI 起来之前，先跑一段（`app_motion.c` 的 `motion_fixed_run()`）：

```
使能 ENA → 设 DIR → 等 20ms → 8500Hz 连续发 10 秒 → 停 → 脱机
```

这与 `stepper_motor` 例程的上电段**逐项同构**，但走的是**本工程自己的 RMT 发射路径**，
所以它的结论对本工程有效。它**绕开**状态机 / 梯形曲线 / UI / 反向间隙 / 位置记账，
是"硬件认不认"与"我们流程对不对"的分水岭：

| 上电固定段的实际现象 | 结论 | 下一步 |
|---|---|---|
| **能连续转 10 秒** | 脉冲链路 + 波形没问题 | 问题在曲线/状态机/参数 ⇒ 看 `Move:` 那行日志的 `曲线：…Hz` |
| **只嗡嗡、不转** | 与曲线/UI 完全无关 | 硬件层：脉宽（②）、电流档、相序、供电（9.9） |

日志关键字（默认 8500Hz × 10000ms）：

```
W 固定段开始：8500 Hz × 10000 ms（约 85000 个脉冲 = 106.25 mm @800 步/mm） 脉宽 0 µs（0 = 50% 方波）
W === 固定段结束（核对 OK）：请求 85000 个脉冲 / 1329 个事务，RMT 报告 86329 个符号；已脱机（轴可手盘） ===
```

`86329 = 85000 + 1329`：多出来的是**每个事务末尾驱动自动补的 1 个结束符**（见 9.7 第 2 步）。
对得上 ⇒ 每一个脉冲都真的出了引脚，再不动就只能查接线 / 驱动器 / 供电。

> ⚠️ **它是真走轴的单向 106mm**（8500Hz×10s ÷ 800 步/mm）。上电前确认两侧行程够；
> 不够就把 `ROLLCOATER_BOOT_HOLD_MS` 改成 2000（≈21mm）或把开关关掉。
> ★ **v12 起该开关默认关闭**（否则每次上电轴都会先跑掉 106mm，且这 10 秒屏幕不响应）。
> 平时要复现这一段用串口命令即可：**`mtest hold [hz] [ms]`**（默认 8500Hz × 10000ms）
> —— 与上电固定段是**同一份代码**，只是按需触发，不占上电时间、不挡 UI。

**② 脉宽默认改成 `0` = 50% 方波（`ROLLCOATER_STEP_PULSE_US`）**

这是频率已经落在 8500Hz 之后**唯一还没与例程对齐的软件变量**：
例程（能转的那版）用的是 **50% 占空比方波**，而本工程 v8 及以前默认 5µs 窄脉冲。
TB6600 是光耦隔离输入、3.3V 直驱时光耦电流仅约 2mA、LED 上升慢 ——
**窄脉冲有被判成"时有时无"的风险**（表现就是"只嗡嗡不转"）。

> 想对比就改 `menuconfig -> Roll Coater HMI -> STEP 高电平脉宽`：
> `0`（50%，例程波形，v9 默认）/ `5`（旧默认）/ `50`；也可在串口里
> `mtest 8500 0` / `mtest 8500 5` / `mtest 8500 50` 各跑一趟直接对比。

**③ 起转那一下发顿/滑步（v10）**

现场反馈"**10 秒固定段能连续转，但起转那一下有点卡**"。这有两个层次的原因，都做了处理：

| 原因 | 现象 | 处理 |
|---|---|---|
| **驱动器"还没醒"就发脉冲**（光耦导通 + 输出级使能 + 转子保持力矩建立要 ms 级） | 起转头几十毫秒像被吞掉，之后才跟上 | v10：`使能稳定时间` 默认 **20ms → 100ms**（`ROLLCOATER_ENA_SETTLE_MS`，可配 5~1000）。仍发顿就往 200/300 试 |
| **补队列被任务调度拖住** → RMT 队列见底 → 脉冲串有断档 | 走起来"一顿一顿" | v10：固定段/`mtest hold` 补队列期间**临时把优先级提到 10**（原来跑在 app_main 的 1 / 控制台的 3），并新增**脉冲落后监视** |
| ★ **转子"瞬间起跳"**（步进电机的**牵入频率 pull-in** 限制：从静止没法瞬间跟上 5.3 转/秒，会滑一下再同步） | 起转**滑/顿一下**，之后 10 秒完全正常 —— 现场 v10 日志已证实：`实测 9.97s 内提交 85000 个脉冲 = 平均 8525 Hz；全程连续，未检出断档` ⇒ **脉冲是连续的，问题在转子** | v11：新增**软启动** —— 曲线/固定段从 `ROLLCOATER_SOFT_START_HZ`（默认 **500Hz**）按 accel 爬到 8500Hz（**67ms / 0.38mm**）。日志：`软启动：500 → 8500 Hz（约 67 ms，加速率 120000 Hz/s）` |

**★★ 软启动的实测结论（v14）：默认关闭 —— 低频爬升反而会"卡壳/左右抖动" ★★**

现场用 v13 加的诊断行抓到的完整证据（一次真实运动，10.000 → 0.001mm）：

```
I Move: 10.000 -> 0.001 mm (-7999 steps, backlash 0, 8500 steps/s = 10.6 mm/s)
I   STEP=IO11 DIR=IO12(0) ENA=IO13(0, 0=使能) 脉冲上限 64 步/事务          ← ENA 是使能的 ✓
I 脉冲核对 OK：请求 7999 个脉冲 / 243 个事务，RMT 报告 8242 个符号        ← 脉冲一个不少 ✓
I   本段实际发射频率 1100 ~ 8500 Hz（243 个事务，平均 32.9 个脉冲/事务）；
    脉冲 7999 个：期望耗时 0.94 s / 实际耗时 1.12 s（比值 1.19）           ← 无断档 ✓
I Arrived at 0.001 mm (-7999 steps)
```

⇒ **软件侧全部正常**（ENA 使能、攒批生效、脉冲连续、到位准确）。
唯一的毛病是**发射频率 1100 → 8500Hz 之间那 ~70ms 的爬升段**：轴被拖过它带不动的频段，
现场手感就是 **"卡壳、左右抖动，然后（到 8500Hz 才）转起来"**。

| 起步方式 | 现象 | 结论 |
|---|---|---|
| **从 1100Hz 爬升**（软启动 500，v11 行为） | 卡壳 + 左右抖动 ~70ms，然后才转 | ✗ 低频段是禁区，爬升等于故意在禁区里走一趟 |
| **直接 8500Hz 起跳**（软启动关闭，v14 默认） | 只在头几毫秒"滑一下"就同步（没有低频段） | ✓ 默认 |

**怎么调（不用重编，1 分钟）**：

```
mtest ss 0        ← 默认：关闭软启动（曲线直接从 8500Hz 起跳）
mtest ss 4000     ← 想"柔一点"就试中间档，数字越接近 8500 爬升段越短
mtest move 10     ← 立刻走一段看起转（期间会打 ENA/DIR 与位置）
```

- `menuconfig -> 软启动起步频率`（`ROLLCOATER_SOFT_START_HZ`，**默认 0**）与 `mtest ss` 是同一项；
  挑到最顺的值后写进 sdkconfig 固化即可。
- 收尾**不受影响**：始终只减速到 8500Hz 就结束（掉进禁区的脉冲电机不走，只会白丢位置）。

**脉冲落后监视**（看日志就能判定是不是软件空档）：

```
W   实测：10.00 s 内提交 85000 个脉冲 = 平均 8500 Hz（目标 8500 Hz）；全程连续，未检出断档
```

- 平均频率 ≈ 目标、且"未检出断档" ⇒ 脉冲串是连续的，**顿感来自机械/驱动器**（转子从静止
  直接跳到 5.3 转/秒必然滑一下再同步 —— **例程的上电段也一样**，那不是故障）；
- 出现 `★★ 固定段中途检出**脉冲落后**：已提交 … / 应按 … 应该到 …（落后 …%）` ⇒ 是软件侧
  断档，把日志发我，我调 RMT 队列深度/批大小；
- 平均频率明显低于目标（差 >10%）同样说明有断档。

> ★ 想更顺的**硬件**方向（软件已到极限 —— 8500Hz 以下这台机器不转，没法用更低频软启动）：
> 提高细分（1/8 → 1/16，同转速下每步更小）、电流档调到电机额定、供电 24V→36V、
> 检查联轴器同心与导轨别劲（反向间隙那 0.2mm 也会在起转时"吃"一下）。
> 换算一句话：**起转的顺滑度由"每步对应的机械位移"决定** ⇒ 细分越高越顺。

**如果这些都不解决**，按顺序（每步一分钟、都不用动接线）：

1. **确认 ENA / DIR 真的到位**：看下发运动那行日志有没有 `★★`（9.9）。
2. **确认脉冲真出了引脚**：`脉冲核对 OK：请求 N / 入队 K，RMT 报告 N+K 个符号`（9.7 第 2 步）。
3. **硬件**：驱动器供电（24V→36V）、电流档、相线分组、机械别劲（9.9）。

#### 9.12.6 想更快/更宽：只能改硬件

| 手段 | 效果 | 备注 |
|---|---|---|
| **驱动器供电 24V → 36V** | ★ 对高速转矩最有效 | TB6600 支持 9~42V；换完**必须重扫** |
| 电流档调到电机额定 | 有效 | 发烫就降一档 |
| 换更大电机/驱动器（DM542 等） | ★ 最可能同时**拉低起跳频率、抬高上限** | 换完按 9.12.3 的表一起改 |
| 改细分拨码（1/8 → 1/4 …） | 同转速所需脉冲率减半 ⇒ **Hz 窗口整体左移** | **必须重算 `5.3×脉冲每圈` 并重扫** |
| 机械：丝杠/导轨别劲、联轴器不同心 | 会明显拉低上限、抬高起跳频率 | 先手动盘轴确认不涩 |

★ **换电机 / 换驱动器 / 改细分 / 改供电之后，必须重扫一次频**，
再把 `MOTION_TURN_FREQ_MIN_HZ`、`MOTION_STEP_FREQ_MAX_HZ`、出厂 `speed`/`accel`
一起改 —— **这几处是配套的，只改一个必然出问题**。
★ 注意出厂 `speed = 15.000mm/s` 是"**12000 ÷ 步数每毫米**"倒推出来的：
改了 `ROLLCOATER_STEPS_PER_UNIT`（换拨码/换导程）之后**这里要跟着重算**。

```

> 注：**起步频率 = 巡航频率**（软启动关闭时），所以 `起步` 与 `巡航` 两个数必然相同；
> 打开了软启动（`mtest ss <hz>`）才会看到 `起步 9000 → 巡航 10000` 这种爬升。
> ★ 若日志里出现 `★★`（DIR/ENA 读回不符 / 脉冲核对异常），按 9.7 / 9.9 查。

##### 9.12.7.1 ★ v15/v13：起步真的就是巡航频率了（工作点 = 12000Hz）

现场曾质疑"**你这不是 12000HZ 吧，启动有问题**" —— 是对的：v9 只改了出厂 `speed`，
**曲线的起步下限还是 v11 的"起跳频率 8500Hz"**，所以日志是
`曲线：起步 8500 Hz → 巡航 12000 Hz`，真实运动**先 8500 再爬到 12000**。

v15 起：**关闭软启动（默认）⇒ 第一拍就是巡航频率**（v10 起出厂值 = 8500Hz），
波形上等价于台架验证过能连续转的 `mtest hold 8500` 那条固定段。

| | v11~v14 | **v15** | **v17（当前）** |
|---|---|---|---|
| 起步下限 | 软启动频率（关软启动时 = 起跳 8500Hz） | **= 巡航频率（关软启动时）⇒ 第一拍就是巡航频率** | 不变 |
| 减速段 | 有（按剩余距离刹到 8500Hz） | 有 | ★ **取消**：整段恒速、到位即停 |
| 收尾 | 减速到 8500Hz 结束 | 不变 | ★ **也是工作频率**（三者相同） |

> ★★ **v17：刹车距离这个概念已经删掉。** v15 那条约束（从巡航刹回 8500Hz ⇒ 约 299 步
> ≈ 0.37mm）建立在"有减速段"之上；v17 整段恒速、到位即停（脉冲一停转子就停），
> 与 `run` + `stop` 一样，**不再需要这段距离**，`motion_begin()` 里那条 WARN 也删了。
> 详见 **9.12.7.2**。

##### 9.12.7.2 ★ v17：把串口 `run` 的发射方式移植进界面运动路径（取消收尾减速）

现场仍报"**正转后反转**"。把两条路的日志逐项对照，唯一的差别是**收尾那一段**：

| | 串口 `run`（现场"转得很好"） | 界面运动（v15，现场"正转后反转"） |
|---|---|---|
| 频率 | **恒定 12000Hz** | 起步/巡航 12000Hz，**末段减速到 8500Hz** |
| 日志 | `连续运行开始：12000 Hz` | `本段实际发射频率 **8620** ~ 12000 Hz` |
| 收尾 | 敲 `stop` 才停（不减速） | 每段末尾都有一个减速段 |

8500Hz 正是这台机器"能转"的**下沿/临界点**（空载能过、**带载发毛**）——
转子在减速段掉进那一带就会打滑、弹回来，现场手感就是"**正转后反转**"。

⇒ **v17 = 曲线整段恒定频率**（起步 = 巡航 = 收尾 = 工作频率；软启动仍默认关闭），
到位就把脉冲停掉。判据 = 日志里这两行，三个频率数必须相同：

```
I   曲线：起步 12000 Hz → 巡航 12000 Hz → 收尾 12000 Hz —— **恒定频率**（无爬升、无减速段…）
I   本段实际发射频率 12000 ~ 12000 Hz（…）
```

★ 附带效果：`MOTION_TURN_FREQ_MIN_HZ`（8500Hz）**不再出现在曲线里**，
它只剩 ① 那条"Speed 下限保护"的作用（低于它会自动抬速并 WARN）。

#### 9.12.8 现在这台机器的"正确使用姿势"

1. 出厂 `speed = 15.000mm/s`（=12000Hz）、`accel/decel = 150mm/s²`（上电即生效），
   **软启动关闭** ⇒ ★ **整段恒定 12000Hz**（起步 = 巡航 = 收尾，无爬升、**无减速段**），
   与串口 `run` 逐项同构（见 9.12.7.2）；
2. 软件的钳制区间是 **10.625 ~ 25 mm/s**（= 8500~20000Hz）：低于 10.625 会被自动抬到
   10.625 并 WARN；高于 25 会被钳并 WARN。
   ★ **不要把 Speed 调到 8500Hz 附近**：那是"能转"的下沿/临界点，带载会出现
   "启动后左右转、跟震动一样"（现场实测）。往上探请逐档试（`f 14000` / `f 16000`）；
3. ★ **没有"刹车距离"这回事了**（v17 取消减速段）：到位即停，行程长短都一样；
   测转速请用 ≥5mm 行程，便于在日志里看匀速段；
4. 什么时候用 `mtest` 复测：**换拨码 / 换供电 / 换电机驱动器**，或出现
   "以前能转、现在不动"且日志里 DIR/ENA/脉冲核对都正常时。

### 9.13 ★★★ STEP(IO11) 波形"断断续续" ⇒ 电机来回/失步：根因与两条发射路径（2026-09-22 现场定案）

**现场现象**：界面里下发目标后，轴"正转反转 / 一顿一顿 / 有时干脆不走"；而串口 `run`
（单向裸脉冲）看起来是好的。前前后后排了很久"方向、曲线、ENA、节奏"，最后**用示波器量 IO11
才定案：方波不连续**。

#### 根因：RMT「每个事务边界」都必然留一个空档

IDF 驱动 `components/esp_driver_rmt/src/rmt_tx.c:601-648` 的 `rmt_tx_mark_eof()`：
一个事务编码完，驱动会紧跟写一个 **`duration0 = 0` 的 stop 符号**
（注释原文："a RMT word whose duration is zero means a stop pattern"）⇒
**硬件在事务边界停一下**，再由"发送完成中断"里的 `rmt_tx_do_transaction()` 启动队列里的
下一个事务。**⇒ 空档长度 = 中断延迟**：

- CPU 闲时：几微秒（所以"台架上、控制台里跑 `run`"看着没问题）；
- CPU 一忙（LVGL 全屏重绘 768KB/帧、WiFi 任务 prio 23、RGB 屏 bounce 的 DMA 中断）：
  几十~几百微秒 ⇒ 示波器上就是"波不连续"。

被这样切碎的脉冲串喂给驱动器，转子就是"推一下、被负载/重力拉回来"⇒ 肉眼"正转反转"。
**这不是"方向"问题**（DIR 全程一个电平）。

#### 解法 A：STEP 改用 **LEDC 硬件 PWM** 直接产生（`MOTION_STEP_PWM_MODE = 1`，**备选**）

- 一段运动 = **启动 PWM**（频率 = 巡航频率、**50% 方波**）+ **按「脉冲数 ÷ 实际频率」定时停止**；
- 中间几万~几十万个脉冲**全由硬件产生**：没有事务、没有队列、没有攒批、没有"发送完成"中断
  ⇒ **原理上不可能断**，软件只在"开始/结束"两个时刻介入；
- 停止入口：① 定时到（到位）② STOP / 返回 / Admin 退出 ③ 报警；另有「预期时长 + 1s」兜底看门狗；
- 资源：LEDC **TIMER_2 / CHANNEL_2**（背光 = TIMER_1/CH0、补光灯 = TIMER_0/CH1，
  见 `app_light.h:40-41`）—— 三者互不冲突；
- 代价：LEDC **不能数脉冲** ⇒ 用时间换算（落点误差 ±1 个脉冲 = **1.25µm**），且必须用
  `ledc_get_freq()` 的**实际值**换算（LEDC 是小数分频：实测请求 12000Hz 实得 **11998Hz**）。

#### 解法 B（★ **当前交付**）：留着 RMT，把它的三处短板补掉（`MOTION_STEP_PWM_MODE = 0`）

现场把 RMT 侧优化之后实测**已经能正常跑**，于是交付就定在 **0**（不用 PWM）：

- `MOTION_RMT_INTR_PRIORITY = 2`：把"事务完成中断"提到高优先级 ⇒ 边界空档从"几十~几百 µs"
  压到 **µs 级**（该档不被允许时自动退回默认，绝不拖挂启动）；
- `MOTION_MAX_STEPS_PER_TX = 190` + RMT 内存 **4 块 = 192 符号** ⇒ **15.8ms/事务**
  （@12000Hz），边界出现次数 ≈ 原来的 1/3（内存申请不到会自动退回 64/2 块）；
- `MOTION_TX_BATCH_MS = 15` ⇒ 队列存货 **~47ms**（抗抢占 ≈×15）。
- 好处：**逐事务精确计数、没有累积误差**（PWM 那条是"时间换算"，落点差 ±1 个脉冲）。
- 通道创建做了**两级兜底**（先减内存、再退优先级），所以"建通道失败 → fatal_hold →
  屏幕不显示"这条路已经封死。

#### 两条路径对照（宏 `MOTION_STEP_PWM_MODE`）

| | `= 1`（PWM，**备选**） | `= 0`（**当前交付**，RMT） |
|---|---|---|
| 波形连续性 | **原理上不可能断**（无事务边界） | 每个事务边界一个"中断延迟"长的空档；已把中断优先级提到 2、事务做到 **190 符号 ≈15.8ms**（`MOTION_MAX_STEPS_PER_TX`）⇒ 空档出现频率降到原来的 1/2~1/4，但**不是零** |
| 落点 | 时间换算，±1 脉冲 | 逐事务精确计数，零误差 |
| 停止 | 定时器 / STOP / 报警即时停 | 队列发完即停 |
| 开机日志 | `★ STEP(IO11) 由 **LEDC 硬件 PWM** 产生（TIMER_2 / CH2，10bit）…` | `★ 本机 STEP 走的是 **RMT 事务路径** …`（WARN） |
| 到位判据 | `脉冲由 LEDC 硬件 PWM 产生：11998 Hz × 2.667 s ≈ 32000 个脉冲` | `脉冲核对 OK：请求 … / … 个事务` + `期望耗时 / 实际耗时 ≈ 1.0` |

> 切换方式：`main/app_motion.h` 的 `MOTION_STEP_PWM_MODE` —— **现在是 `0`（RMT，交付）**；
> 想看 PWM 对照就改成 `1` 重编，再改回 `0` 即复位。**别删任何一条路**（这是唯一能 A/B 的对照手段）。
> 开机日志会如实报出当前跑的是哪条：RMT 会打 `★ 本机 STEP 走的是 **RMT 事务路径**…`（WARN，
> 不是报错），PWM 会打 `★ STEP(IO11) 由 **LEDC 硬件 PWM** 产生…`。

#### 踩过的两个坑（改这段代码前必读）

1. **反向运动时 `s_cmd_target - s_cmd_start` 是负数** ⇒ PWM 一取 `uint32_t` 就变成 **42 亿**个脉冲
   （定时 ≈ **99 小时**）⇒ 现场现象是"**反方向一直转不停**"（日志里会打出
   `× 4294935297 个脉冲 ≈ 357970.937 s`）。**必须取绝对值。**
2. **PWM 模式没有"曲线逐拍推进"** ⇒ ① `s_last_dir` 要自己提交（否则**反向间隙补偿永远不生效**，
   日志里 `backlash 0` 就是证据）；② 到位时要把 `s_pos_steps` 对齐到 `s_cmd_target`
   （命令域累计基准，否则下一段起点会偏）。

#### 顺手做的两件事

- **DIR 的设值/读回都打进日志**：`STEP=IO11 DIR=IO12(设 1 / 读回 1) ENA=IO13(0, 0=使能)`。
  判据：正转/反转两条命令的 DIR 必须不同（1 / 0）；设值与读回必须一致（不一致 = 引脚被外部拉住）。
- **静止 2 秒自动脱机**（`MOTION_IDLE_RELEASE_MS = 2000`）：现场"马达停了之后嗡嗡响"是
  **保持电流**；静止够 2s 就抬 ENA 脱机，下次下发目标自动重新使能。
  ⚠️ 前提：**脱机期间负载不能把轴推动**（本工程没有编码器，推走就"账实不符"）。
